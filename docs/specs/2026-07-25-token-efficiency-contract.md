# 스펙: 하네스 토큰 효율 계약

- 날짜: 2026-07-25 / 상태: 구현됨
- 관련: `_workspace/harness-review-2026-07-25-token-efficiency/`, ADR 032

## 배경

최근 28일 AgentsView 실측에서 사람 하네스 세션 36개에 Agent 호출 92회가 발생했고, 두 고비용 세션은 각각 15회 호출했다. 호출의 49회가 reviewer였으며 같은 자동 주입 문서와 스킬 본문을 세션 안에서 여러 번 다시 읽었다. 프롬프트 캐시 적중률은 이미 96.6%이므로 고정 문서만 축소하는 것보다 호출·턴·재독을 먼저 줄여야 한다.

## 목표

- 필수 검증을 유지하면서 중복 에이전트 발행과 재검증 비용을 줄인다.
- 자동 주입 문서와 이미 읽은 파일은 변경분만 다시 읽는다.
- 긴 세션은 완료된 작업 경계에서 손실 없이 교체한다.
- 도구·에이전트·사용자 출력은 판단에 필요한 정보만 기본 반환한다.
- 스킬 자동 라우팅 의미를 유지하면서 상시 노출 설명과 Claude 전용 앵커를 압축한다.

## 비목표

- 검증·보안·인프라 관점을 비용 때문에 생략하지 않는다.
- reviewer의 모델 또는 추론 등급을 낮추지 않는다.
- `AGENTS.md` 필수 규칙을 추가로 이동하거나 삭제하지 않는다.
- Aider 등 외부 저장소 맵 도구를 상시 의존성으로 설치하지 않는다.
- 진행 중인 작업을 임의로 중단하거나 압축해 이월 손실을 만들지 않는다.

## 요구사항

1. **R1 — 발행 예산·재사용:** `orchestrate`와 `team-review`는 Phase 0에서 예상 Agent 호출 수를 기록한다. 같은 역할·관점의 후속 검증은 새 에이전트보다 기존 에이전트에 델타 재검증을 우선 요청한다. 새로운 독립 위험 축이나 기존 에이전트 이용 불가일 때만 추가 발행한다.
2. **R2 — 검증 보존:** 코드·보안·인프라·스펙 완료 기준의 기존 필수 독립 검증은 발행 예산의 예외가 아니라 먼저 확보해야 하는 최소 비용이다.
3. **R3 — 읽기 1회·델타 패킷:** 자동 주입된 루트 `AGENTS.md`는 전문 재독하지 않는다. 선택한 스킬·프로젝트 하네스·스펙·diff만 읽고, 같은 파일은 내용 해시/mtime 변경·compaction·근거 충돌 때만 다시 읽는다. 단계 간 전달은 목표, 결정, 변경 파일, diff 또는 경로, 최신 테스트, 미검증 범위만 담은 델타 패킷을 사용한다.
4. **R4 — 세션 경계:** 작업 단위가 완료됐고 peak context가 약 150k를 넘으면 `carryover` 또는 `work-tracker`로 증거·결정·다음 단계·미검증 범위를 넘기고 새 세션을 권고한다. 작업 도중의 강제 교체는 하지 않는다.
5. **R5 — 출력 계약:** 원시 로그와 상세 증거는 `_workspace/`에 저장하고 에이전트 반환은 결론, finding index, 증거 포인터, 미검증 범위만 담는다. 진행 알림은 1~2문장, 기본 완료 답변은 결과·핵심 증거·미검증 범위로 제한하되 안전 결정·실패 분석·이해도 퀴즈는 예외다.
6. **R6 — 도구 출력:** 탐색 읽기와 diff는 설치된 경우 `rtk` 또는 범위 지정·필터링을 우선한다. 완료 증거는 원문 또는 tee 원본을 보존해 압축 출력만으로 PASS를 주장하지 않는다.
7. **R7 — 상시 노출 예산:** 17개 루트 스킬 description의 UTF-8 합계는 9,000바이트 이하이고 각각 기존의 핵심 양성 트리거, 인접 스킬 부정 경계, 재실행 키워드를 유지한다. `CLAUDE.md`는 5,500바이트 이하이며 `@AGENTS.md`, 한국어 출력, 핵심 라우팅, 스킬 우선순위, 인터뷰·이해도 전달 게이트를 유지한다.
8. **R8 — 기계 회귀:** integrity-check가 R7의 두 예산을 검사하며 경계값 회귀 테스트가 존재한다. 행동 계약 테스트가 R1~R6의 필수 문구와 역할 배치를 검사한다.
9. **R9 — 이력 보정:** 이번 변경은 `5afc353`의 같은-커밋 changelog 누락을 현재 changelog에 소급 기록한다.

## 인터페이스 / 설계 개요

- `.agents/skills/orchestrate/SKILL.md`: 발행 예산, 에이전트 재사용, 델타 패킷, 세션 경계의 단일 실행 절차.
- `.agents/skills/team-review/SKILL.md`: 관점 선택 후 호출 예산과 동일 reviewer 델타 재검증 계약.
- `.agents/agents/*.md`: 읽기 1회와 짧은 반환 형식의 공통 역할 계약.
- `.agents/hooks/integrity-check.py`: 스킬 description 합계 및 `CLAUDE.md` 바이트 예산의 결정론적 검사.
- `CLAUDE.md`와 각 `SKILL.md` frontmatter: 자동 로딩되는 최소 라우팅 표면.
