# 스펙: 장기 실행 로그 보존과 전체 스위트 실행 한도

- 날짜: 2026-10-07 / 상태: 구현됨
- 관련: AGENTS.md §13-2

## 배경
사용자가 출력 잘림 때문에 장기 명령을 다시 실행하지 않고 저장한 로그를 분석하도록 요청했다. 전체 스위트는 변경 직후와 최종 확인 각 1회로 제한한다.

## 목표
출력 표시와 실제 실행 결과를 구분하고 동일 작업에서 전체 스위트를 중복 실행하지 않는다.

## 비목표
새 실행기·자동 차단 훅, 테스트 생략, 실패의 성공 처리, 실제 사용량 절감률 측정은 포함하지 않는다.

## 요구사항
1. R1: 장기 명령의 stdout·stderr를 실행별 파일에 리다이렉트하고 명령·작업 디렉터리·대상 리비전 또는 변경 상태·종료 코드를 남긴다. 로그는 덮어쓰지 않는다.
2. R2: 표시 잘림만으로 재실행하지 않고 저장 파일에서 필요한 범위를 분석한다. 실패·시간 초과·취소·불완전 결과는 그대로 보고한다.
3. R3: 같은 작업에서 호스트·작업자·리뷰어를 합쳐 전체 스위트는 변경 직후 최대 1회, 최종 최대 1회다. 실패·시간 초과·취소 시도도 횟수에 포함한다. 중간 수정과 독립 검증은 관련 테스트로 수행하며 분할·재위임으로 한도를 초기화하지 않는다. 최종 실행 실패는 미완료로 보고하고 관련 테스트로 수정·검증하며 한도를 넘어 전체 스위트를 다시 실행하지 않는다.
4. R4: SDD/TDD와 독립 리뷰 의무는 유지한다. 전체 스위트가 필요하지 않은 변경에서 2회를 채우기 위한 실행은 하지 않는다.

## 인터페이스 / 설계 개요
루트 §13-2에 핵심 규칙과 `orchestrate/references/test-execution.md` 참조를 추가하고 reviewer 역할은 관련 테스트 재실행이 전체 스위트 중복 실행을 뜻하지 않음을 참조한다. 명령 결과 전달은 상태·핵심 요약·원본 파일 경로로 충분하다. 새 API나 실행 상태 기계는 없다.

## 완료 기준 (테스트 가능한 형태)
- [x] C1 (R1–R3): 계약 테스트가 로그 보존·표시 잘림 재실행 금지·공유 한도·실패 보존을 확인한다.
- [x] C2 (R3–R4): 합성 압박 시나리오에서 저장 로그를 읽고 최종 슬롯을 보존하며 관련 테스트로 독립 검증한다. 실제 사내 관측으로 기록하지 않는다.
- [x] C3 (R1–R4): AGENTS 한국어 뷰와 역할 한국어 요약에 대응 규칙을 반영하고 정합성 검사·독립 리뷰를 통과한다. docs/README.md에는 이 스펙 링크·상태만 추가한다.

검증 근거: 계약 검사 2개와 정합성 검사 55개 통과, 독립 reviewer PASS. 전체 저장소 스위트는 필요하지 않아 0회 실행했다. 합성 사전 판단은 이미 로그 재사용을 선택했고, 규칙 적용 후 확인도 준수했다. 따라서 행동 개선 실측이나 절감률은 주장하지 않는다. 원본 로그·실행 기록·리뷰는 `_workspace/long-command-logs/`에 보존했다.

## 미해결 질문
없음. 사용자 요청으로 한도가 확정됐다. 연결 지식 소스는 시간 초과로 읽지 못했다. 최종 스위트 이후 추가 전체 실행이 필요한 상태에서는 미검증 범위를 보고한다.
