# 스펙: harness-review-reminder 훅 — 주간 점검 자동 트리거

- 날짜: 2026-07-14 / 상태: 구현됨
- 관련: 루트 AGENTS.md 8절(주 1회 관찰), harness-review SKILL.md, docs/specs/2026-07-14-agentsview-daemon-hook.md(훅 규격 선례)

## 배경

8절은 진화 트리거 3신호를 "주 1회 관찰"하는 운영 습관을 요구하지만, 실행이 사용자 기억("주간 점검"이라고 말하기)에 의존한다 — 기억 의존 습관은 몇 주 안에 증발한다(사용자 요청, 2026-07-14: cron화). OS cron + 헤드리스 실행 대신 **SessionStart 훅이 경과를 판정해 세션 컨텍스트에 실행 지시를 주입**하는 방식을 택한다. 이유: ① harness-review의 제안은 사용자 승인이 필수(무단 생성 금지)라 사람이 있는 세션에서 돌아야 하고 ② 신호 데이터(agentsview DB·REGISTRY.md·`_workspace/`)가 로컬 세션 환경에 있으며 ③ 무인 헤드리스 실행은 승인자 없이 토큰만 소모하고 ④ OS 3종(cron/launchd/작업 스케줄러) 등록은 유지 비용이 크다.

## 목표

- **2단 주기 자동 트리거** (2026-07-14 사용자 확정 — "일주일은 너무 길다"): ① 마지막 **전체 점검** 후 7일 경과 → 전체 모드(신호+무결성) 지시 주입. ② 전체는 7일 이내지만 마지막 점검 후 1일 경과 → **일일 경량 모드**(마지막 점검 이후의 확장 신호 ①~③ 스캔만 — ④ 수축·효율은 3주 관찰 창이 필요해 주간의 몫) 지시 주입.
- 둘 다 기한 내면 **무출력(침묵)** — 점검할 게 없으면 채팅에 상태 줄을 남기지 않는다(2026-07-16 사용자: "오늘은 이미 했다"는 줄이 세션마다 반복되는 노이즈). 가시성은 점검이 필요할 때(full·daily)만 남기고, 훅 동작·설치 검증은 harness-install의 몫이다. (2026-07-14에는 "정상 동작 vs 훅 미실행 구분"을 위해 기한 전에도 상태 한 줄을 냈으나, 매 세션 노이즈 비용이 그 가시성 가치보다 커 재개정했다.)
- 경과일 판정의 "오늘"은 **한국 표준시(KST, UTC+9)** 기준이다 — 컨테이너가 UTC면 일일/주간 경계가 사용자 타임존과 하루 어긋난다(2026-07-16 사용자 지적).
- **사내 설치처에서는 일일 모드를 발동하지 않는다**(2026-08-03 사용자 요청). 사내 프로필은 추적 하네스 파일의 수정·커밋·푸시가 전부 금지되므로(§5·ADR 012), 일일이 찾는 확장 신호 ①~③은 그 기계에서 적용될 수 없고 `_workspace/harness-updates.md` 대기 큐에 쌓이기만 한다. **주간은 유지한다** — 무결성 점검(심볼릭 링크 파손·Codex 어댑터 드리프트)은 하네스를 고치지 않아도 사내에서 즉시 값이 있다.

## 비목표

- 무인(헤드리스) 자동 실행 — 제안 승인에 사람이 필요하다. 훅은 트리거만 하고 실행은 세션의 모델이 한다.
- ~~Codex 세션 트리거(훅은 Claude Code 계층)~~ — **Codex 범위로 승격(ADR 019·031)**: `.codex/config.toml` 인라인 SessionStart로 등록되고, trust된 CLI 0.145.0 macOS 세션에서 stdout의 developer context 주입을 실측했다.
- 점검 자체의 수행(harness-review 스킬의 몫).

## 요구사항

- R1: 마커 2개 — 전체 `_workspace/.harness-review-last`, 일일 `_workspace/.harness-review-daily-last`(내용: `YYYY-MM-DD` 한 줄) — 로 각각 경과일을 계산한다. 기준 디렉토리는 `CLAUDE_PROJECT_DIR`(부재 시 cwd).
- R2: 마커가 없거나, 내용이 파싱 불가하거나, **존재하되 읽기 실패(권한·I/O)**하면 해당 주기의 "기록 없음"(경과)으로 간주한다(첫 설치·유실 시 즉시 점검 유도). 실패 방향은 침묵이 아니라 점검 유도다 — 읽기 예외가 main까지 새면 fail-open이 삼켜 리마인더가 영구 침묵한다(2026-07-16 감사 HOOK-F6).
- R3: 모드 판정 — 전체 마커 7일 이상(또는 기록 없음)이면 **full**, 아니고 일일 마커 1일 이상(또는 기록 없음)이면 **daily**, 둘 다 아니면 **무출력(침묵)** — 점검할 게 없으면 채팅에 남기지 않는다(2026-07-16 재개정: "이미 했다" 상태 줄은 매 세션 노이즈. 가시성은 full·daily에서만, 설치 검증은 harness-install). full·daily 지시에는 **첫 응답에서 점검 서브에이전트를 explorer 타입으로 백그라운드 즉시 발행**(harness-review 스킬 '실행 방식' 절 — 메인 루프 직접 수행 금지, 사용자 요청 병행 처리. 발행 타입 explorer를 메시지에 명시한다 — 스킬 명문화 후에도 리마인더 경로 발행 3회 중 2회가 general-purpose로 유출된 실측, 2026-07-17 신호 ③)과 완료 시 결과의 채팅 보고, 마커·운영 로그 갱신 주체(서브에이전트)와 확인 안내를 포함한다 — 훅은 모델을 깨우지 못하므로 지시는 첫 사용자 턴에서 소비되는데, 메인 루프 직접 수행은 첫 응답을 점검이 점유해 사용자 요청과 경합한다(2026-07-14 사용자 확정: 서브에이전트 위임).
- R4: fail-open — 예외 발생 시 무출력 exit 0. 어떤 경우에도 exit 0(세션 시작을 막지 않는다). 시작 시 stdout을 **UTF-8(errors=replace)로 재구성**한다 — 한글 Windows 콘솔(cp949)은 메시지의 em dash를 인코딩하지 못해 print가 예외를 던지고, fail-open이 그것을 삼켜 리마인더가 **무출력으로 조용히 죽는다**(2026-07-14 장애 — exit 0이라 발견도 안 됨).
- R5: 마커 갱신은 harness-review 스킬이 점검 완료 시 수행한다(전체 → 두 마커, 일일 → 일일 마커. 이 훅은 읽기 전용). 마커에 쓰는 오늘 날짜도 **KST 기준**이다(R7과 일치 — 읽기·쓰기 타임존이 어긋나면 하루 오차).
- R6: 회귀 테스트가 `.agents/hooks/harness-review-reminder_test.py`로 영속되어야 한다.
- R7: 경과일 계산의 "오늘"은 **KST(UTC+9 고정 오프셋 — 한국은 DST 없음)**로 산정한다(`datetime.datetime.now(KST).date()`). zoneinfo·tzdata 의존 없이 고정 오프셋으로 구현해 이식성을 유지한다.
- R8: **설치처 프로필이 `사내`면 daily 모드를 침묵**시킨다(full은 영향 없음). 판정 입력은 기준 디렉토리의 `REGISTRY.md` 「## 설치처 프로필」 절이며, **그 절 안의 굵은 라벨 목록 항목**(`- **개인**` / `- **사내**`)만 읽는다. **이 저장소의 현재 파일에서는 절 한정이 없어도 결과가 같다** — 2026-08-03 기준 같은 정규식을 파일 전체에 적용하면 매치가 1건(8행, 프로필 줄 자체)뿐이다. `REGISTRY.md`는 미추적이고 설치처마다 다르며 계속 편집되므로 이 수치는 **상태 의존**이다(같은 날 「배포처 이관 경계」 절의 `개인` 3회·`사내` 0회도 마찬가지). 절을 한정하는 근거는 현재 오독이 아니라 **형식 가정을 좁히는 것**이다: 다른 절이 이미 같은 두 단어를 산문으로 쓰고 있고, 그중 어디에 굵은 라벨 목록이 생기면 파일 전체 검색의 첫 매치가 프로필이 아닐 수 있다. 절 한정은 그 경우를 구조적으로 배제한다. **코드 펜스(```) 안의 내용은 읽지 않는다** — 형식 예시가 실제 프로필로 읽히면 그 설치처의 값이 아닌 것으로 일일이 꺼진다(억제 방향 위양성, 2026-08-03 독립 검증 F4). **미상은 억제하지 않는다** — 파일 부재·절 부재·형식 불일치·판독 실패(권한·인코딩)는 전부 프로필 미상이고, 미상일 때는 기존 동작(daily 발동)을 유지한다. 억제 방향으로 fail하면 개인 설치처에서 판독이 한 번 어긋난 순간 일일 점검이 영구 침묵하며, 이는 R2가 마커에 대해 고정한 실패 방향과 같은 논리다. 억제 시에는 안내 줄도 남기지 않는다(R3의 침묵 결정과 동일 — "오늘은 끕니다"가 매 세션 노이즈가 된다).

## 인터페이스 / 설계 개요

- 등록: 루트 `.claude/settings.json` → SessionStart(**matcher `startup|resume|clear`** — compact에는 재실행하지 않는다), Codex → `.codex/config.toml` 인라인 SessionStart. command는 **인터프리터 탐색 체인** `for p in python3 python py; do "$p" -c "" >/dev/null 2>&1 && exec "$p" "$CLAUDE_PROJECT_DIR/.agents/hooks/harness-review-reminder.py"; done; exit 0` (Codex는 `$PWD` 경로) — 실행 확인(`-c ""`)으로 Windows Store 스텁을 거르고 인터프리터 부재 시 exit 0(fail-open).
- 입력: 없음(stdin 무시). 읽는 파일은 마커 2개와 `REGISTRY.md`(R8 프로필 판정) 셋뿐이다. 출력: 경과 시 stdout 한 줄(세션 컨텍스트로 주입됨), 아니면 무출력. 항상 exit 0.
- 부수 효과 없음 — 파일 읽기뿐(R5: 쓰기는 스킬이 담당).
- R8의 프로필 분기는 **훅 코드(추적 파일)에 있고 판정 입력은 미추적 `REGISTRY.md`에 있다**. 그래서 사내 설치처는 자기 기계의 추적 파일을 하나도 고치지 않고도 프로필 한 줄로 이 동작을 얻는다 — 개인 설치처에서 코드를 넣고 `git pull`로 내려받으면 된다(§5의 사내 수정 금지와 충돌하지 않는 유일한 배치).

## 미해결 질문

없음. Codex CLI 0.145.0 macOS의 trust된 프로젝트에서 인라인 SessionStart stdout이 developer context에 들어오는 것을 실측했다. clone 직후 trust 이전과 Windows는 보장 범위 밖이다(ADR 031).

**R8의 검증 한계(2026-08-03)**: 이 저장소의 프로필은 `개인`이므로 R8 분기는 **이 기계에서 행동을 바꾸지 않는다**(실측: `read_profile('.')` → `'개인'`). 즉 실환경 확인은 사내 설치처가 이 커밋을 내려받은 뒤에야 가능하고, 현재 근거는 회귀 테스트(C11~C14)와 임시 디렉토리 위의 프로필 파일 시뮬레이션뿐이다. 사내 설치처에서 첫 세션이 돌 때 **일일 리마인더가 실제로 나오지 않고 주간은 나오는지** 확인해야 완결된다.

**R8의 정당화 사례 점검 결과(metaskill 공통 규칙 15, 독립 검증 2026-08-03에서 지적)**: ① **드래프트한 조건은 인용된 정당화 사례에 발동하지 않는다.** 비용 근거로 든 두 회차(2026-07-31 `agent-af1c60f6bea1d2701`, 2026-08-03 회차)는 모두 `개인` 프로필 세션이므로 `profile == '사내'`가 거짓이고 R8은 그 회차들을 억제하지 않았을 것이다. 그 수치가 보여주는 것은 **억제 대상 회차 하나의 크기**이지 사내에서 낭비가 발생했다는 측정이 아니다. ② **관장 표면에 측정된 실패는 0건이다** — 이 설치처에 사내 프로필 기계가 아직 없다(`REGISTRY.md`의 설치처 프로필 절: "개인 기계는 이 한 대다", 2026-07-27 사용자 확인). ③ 따라서 **이 분기의 발행 근거는 §8 진화 신호가 아니라 사용자의 직접 지시**다. 규칙 15가 요구하는 최소 조건을 만족하지 못한 채 나간 것이고, 그것을 감수한 근거는 실패 방향이 fail-open이라 오판의 상한이 "일일 점검이 예정대로 도는 것"이라는 점이다. 사내 첫 세션 확인(위 문단)이 이 공백을 메우는 지점이다.
