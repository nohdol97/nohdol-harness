# Paperclip 하네스 동기화

## 배경·목표
사용자가 nohdol-harness의 역할과 스킬을 Paperclip에서 직접 관리하도록 이식을 요청했다. 하네스 원본을 유지하면서 반복 적용 가능한 동기화와 실행 방식 연결을 제공한다.

## 비목표
제품 작업 시작, 에이전트 모델의 품질 평가, 배포·머지 자동화, 기존 autoloop 폐기, 기존 Paperclip 에이전트 설정 일괄 교체는 포함하지 않는다.

## 요구사항
- R1: 루트 표준 에이전트 7종과 스킬 전체를 실제 원본에서 읽는다. 설치 ID·절대 경로·모델 선택·생성물은 미추적 설치 상태로 둔다.
- R2: 적용 전 계획을 출력하고, 적용은 명시적 --apply에서만 한다. 같은 원본을 재적용해 역할·스킬이 중복 생성되지 않아야 한다.
- R3: 생성 역할에는 원본 역할 문서와 공통 Paperclip 연결 지침을 연결한다. 원본 역할·스킬은 수정하지 않는다.
- R4: Paperclip이 티켓·의존성·위임·재검토 상태를 소유한다. 동일 작업에 autoloop과 native subagent 스케줄링을 중첩하지 않는다. 품질·안전 규칙은 유지한다.
- R5: 기존 chief-of-staff와 프로젝트를 재사용한다. 기존 지침은 보존하고 구분된 연결 안내를 추가한다. 무관한 에이전트·스킬과 설정은 보존한다.
- R6: 신규 역할은 주기 실행을 끄고 실제 업무를 생성하지 않는다. 에이전트 설정·스킬 연결·계정 hello test를 확인한다.
- R7: prompt의 도구 목록을 실제 권한으로 주장하지 않는다. CLI sandbox를 명시하고, 읽기 역할은 제품 수정을 허용하지 않으며 결과는 Paperclip 댓글로 전달한다. 훅 신뢰·제품 E2E 미검증 범위를 보고한다.
- R8: 인증 토큰을 코드·로그·산출물에 저장하지 않는다. 루프백 인스턴스만 대상으로 하고 동명 외부 자산을 덮어쓰지 않는다. 실패는 비정상 종료하고 재실행으로 수렴한다.

## 완료 기준
- [x] C1: 원본에서 7개 역할·현재 스킬 집합을 발견하고, 각 역할의 원본 경로와 hash가 생성 지침에 남는다.
- [x] C2: dry-run은 API 읽기만 수행하며, 동기화 전후 재적용 시 중복 역할과 스킬이 없다.
- [x] C3: Paperclip에서 역할별 지침·스킬·관리자 관계·모델 설정을 조회해 기대값을 확인한다.
- [x] C4: 기존 관리자 지침·다른 설정과 사용자 작업 파일은 보존된다. 충돌 또는 foreign asset에는 쓰기를 거부한다.
- [x] C5: 모든 스킬의 필요한 참조 파일을 가져오며 로컬 원본 경로를 지침에서 안내한다. 실행기·훅을 단순 문서 복사로 활성화했다고 주장하지 않는다.
- [x] C6: 계정·실행 환경 hello test와 서버 health가 통과한다. 제품 작업 실행 수는 동기화로 증가하지 않는다.
- [x] C7: 의미 있는 회귀 테스트, 하네스 무결성 검사, 독립 검토가 통과하며 재동기화 명령과 한계를 문서화한다.
