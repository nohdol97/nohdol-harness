# 스펙: 루트 하네스 기능·언어 총체 감사

- 날짜: 2026-08-14 / 상태: 구현됨
- 관련: 사용자 요청 「하네스 기능적·총체적 검토 및 모호한 한국어 표현 즉시 수정」

## 배경

루트 하네스는 안전 규칙, 작업 라우팅, 역할 정의, 스킬, 실행 훅, Claude Code·Codex 설정을 함께 관리한다. 기능이 여러 파일에 분산되어 있으므로 문서만 읽거나 테스트만 실행해서는 전체 상태를 판단하기 어렵다. 또한 현재 한국어 사용자용 문서에는 긴 문장 안에 조건·예외·근거가 겹치거나 내부 용어를 설명 없이 쓰는 부분이 있어, 규칙의 의도를 아는 사람에게만 읽히는 문제가 있다.

## 목표

- 현재 활성 규칙과 실행 장치가 서로 일치하는지 확인하고 발견한 결함을 수정한다.
- 사용자가 실제로 읽는 현재 상태 문서의 한국어를 뜻을 바꾸지 않는 범위에서 명확하게 고친다.
- 수정 결과를 자동 검사와 독립 검토로 다시 확인한다.
- 사용자가 변경 이유와 중요한 판단 갈림길을 따라갈 수 있는 읽기 순서를 제공한다.

## 비목표

- 과거 결정을 보존하는 ADR, 제안서, 완료된 스펙, 변경 이력의 옛 행을 현대 문체로 전면 재작성하지 않는다. 과거 기록을 고치면 당시 판단 근거가 바뀐 것처럼 보일 수 있기 때문이다.
- 하위 제품 프로젝트의 코드와 하위 하네스는 이번 수정 대상에 포함하지 않는다. 다만 루트 라우팅과의 연결 상태는 검사한다.
- 기존 안전 정책, 설치처 정책, 모델 티어 정책을 취향에 따라 완화하거나 강화하지 않는다. 정책 변경이 필요한 결함은 근거와 충돌 지점을 먼저 명시한다.

## 요구사항

1. **R1 — 구조 감사:** 루트 규칙, Claude Code·Codex 로더, 에이전트·스킬 목록, 훅 등록, 문서 인덱스, 설치처 레지스트리의 연결 상태를 검사한다.
2. **R2 — 실행 검증:** 저장소가 제공하는 훅·무결성·계약 테스트를 현재 작업 트리에서 실행하고 실패를 수정한다.
3. **R3 — 규칙 일관성:** 활성 규칙 사이의 모순, 도달할 수 없는 절차, 중복된 권위 선언, 문서와 실행 장치의 불일치를 찾아 수정한다.
4. **R4 — 한국어 명료성:** 현재 사용자용 진입 문서에서 함축어, 설명 없는 내부 용어, 주어가 없는 의무문, 한 문장에 겹친 조건·예외를 찾아 평이한 문장으로 고친다. 의무·예외·발동 조건의 의미는 보존한다.
5. **R5 — 추적성:** 변경 파일, 검증 명령, 관찰 결과, 남은 미검증 범위를 변경 이력과 작업 보고에 기록한다.
6. **R6 — 독립 검토:** 기능 정확성, 규칙·구조 일관성, 한국어 이해 가능성을 서로 다른 관점에서 검토하고, 근거 없는 지적은 제외한 뒤 최종 판정을 낸다.

## 인터페이스 / 설계 개요

감사는 `규칙·문서 → 실행 설정·훅 → 자동 검사 → 관점별 검토 → 수정 → 재검증` 순서로 진행한다. 각 단계는 앞 단계의 산출물을 입력으로 받는 단일 흐름이므로 별도 다이어그램은 넣지 않는다.

한국어 수정은 활성 사용자 진입면을 우선한다. 핵심 대상은 `README.md`, `AGENTS.ko.md`, `.agents/agents/README.ko.md`, `.agents/skills/README.ko.md`, `REGISTRY.md`다. 과거 기록은 검색과 근거 확인에는 사용하지만 문체 개선 대상으로 일괄 수정하지 않는다.

## 완료 기준 (테스트 가능한 형태)

- [x] C1 (R1): 구조·로더·목록·등록을 검사하면 누락과 드리프트가 0건이거나, 남은 항목이 위치와 사유와 함께 보고된다.
- [x] C2 (R2): 루트 훅·무결성·계약 테스트를 새로 실행하면 모두 통과하고, 명령·관찰 출력·입증 범위가 기록된다.
- [x] C3 (R3): 활성 규칙의 동일 축 권위 선언을 검색하면 서로 모순되는 미해결 주장이 0건이거나, 보류 사유가 근거와 함께 보고된다.
- [x] C4 (R4): 우선 대상 문서를 문장 단위로 검토하면 새로 발견한 함축어와 다중 조건 문장이 평이한 한국어로 바뀌고, 바뀐 문장의 의무·예외·발동 조건이 원문과 같음을 대조할 수 있다.
- [x] C5 (R5): 변경 이력의 대상 목록과 실제 변경 경로를 대조하면 누락이 0건이고, 작업 보고에 검증 명령·출력·입증 범위·미검증 범위가 모두 있다.
- [x] C6 (R6): 독립 검토의 모든 필수 수정 항목이 반영되고 델타 검토가 PASS를 내리거나, 해결하지 못한 항목이 위치·위험·이유와 함께 사용자에게 보고된다.
- [x] C7 (R4·R5): 최종 보고를 읽으면 사용자가 주요 결정 갈림길과 변경 파일을 볼 순서를 알 수 있다.

## 주요 판단 갈림길

1. **활성 안내를 고칠지, 과거 기록까지 다시 쓸지** — 현재 사용 지침만 평이하게 고치고 과거 변경 이력은 당시 증거로 보존했다.
2. **용어집을 따로 둘지, 읽는 자리에서 정의할지** — 사용자가 첫 화면에서 이해할 수 있도록 역할·상태 용어를 각 진입 문서 안에서 바로 설명했다.
3. **카탈로그를 전체 계약으로 만들지, 짧은 길잡이로 둘지** — 한국어 카탈로그는 역할·사용 시점·경계를 짧게 보여주고, 정확한 조건은 영어 원본을 단일 원본으로 유지했다.
4. **Codex 도구명만 고정할지, 실제 페이로드까지 고정할지** — 도구명만 고친 1차 테스트가 거짓 초록을 냈으므로 `agent_type`·`message` 필드까지 R18이 검사하게 했다.
