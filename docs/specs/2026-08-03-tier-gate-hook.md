# 스펙: tier-gate 훅 — 서브에이전트 발행의 9절 모델 지정 강제

- 날짜: 2026-08-03 / 상태: 구현됨
- 관련: **ADR 037**(이 훅의 결정), 루트 AGENTS.md 9절(티어→모델 매핑), 10절(에이전트 정의 tier 필드), ADR 005(탈모델명), ADR 023·028·029(게이트 실행 계층 승격 선례·Codex 파리티)

## 배경

9절은 티어별 모델을 규정하지만 **적용은 발행 시점의 `model` 파라미터로만 이뤄진다** — 지정하지 않으면 서브에이전트가 부모 세션의 모델을 그대로 상속한다. 그래서 이 표는 선언된 이래 한 번도 적용된 적이 없고, 세션 모델이 무엇이냐에 따라 **어느 티어가 위반 상태인지만 뒤바뀌었다.**

실측(2026-08-03, 이 설치처 로컬 세션 로그 `~/.claude/projects/<루트>/*/subagents/*.jsonl`):

| 구간 | explorer(explore 티어) | design 티어(reviewer 등) |
|---|---|---|
| ~2026-07-22 | 표준 11 / 상위 4 (대체로 준수) | **표준 25 / 상위 11 — 검증 25건이 저성능 모델** |
| 2026-07-25~ | **상위 21 / 표준 3 — 역전** | 상위(우연히 준수) |

수치는 세션이 쌓이면 늘어나는 **상태 의존값**이며 위 값은 2026-08-03 집계다(측정 중에도 이 세션의 발행으로 증가했다). 재현되는 것은 개별 숫자가 아니라 **구간 간 역전과 그 단일 원인**이다.

앞 구간의 위반이 더 무겁다. 검증을 저성능 모델로 돌리는 것은 사용자 전역 정책이 **절대 금지**한 상태이고(false negative가 완료된 작업을 재작업시킨다), 9절이 경량 모델 금지를 따로 못박은 이유이기도 하다. 두 구간을 겹쳐 보면 원인은 하나다 — **발행 시 `model`을 지정하지 않는다.**

문서 규칙을 더하는 것으로는 고쳐지지 않는다는 근거도 같은 데이터에 있다: 9절은 처음부터 이 표를 갖고 있었고, 그럼에도 상속이 늘 이겼다. 반면 **에이전트 타입**은 2026-07-17에 리마인더 훅 문구로 처방한 뒤 37건 전부 explorer로 유지됐다 — 발행 지점에 놓인 장치는 버텼다.

## 목표

- 티어가 선언된 에이전트를 `model` 없이 발행하면 **차단**하고, 9절 표를 읽고 지정하라고 지시한다.
- **무엇을 골랐는지는 판정하지 않는다**(ADR 005 탈모델명).
- 하네스 로스터 밖 에이전트와 판독 실패는 통과시킨다(fail-open).

## 비목표

- **추론 등급 강제** — Claude Code의 Agent 도구는 `effort` 파라미터를 노출하지 않는다(실측: `tool_input` 키는 `description`·`prompt`·`subagent_type`·`model`·`run_in_background`). 서브에이전트는 부모 세션 등급을 상속하며, payload 최상위의 `effort`는 그 상속값이 기록된 것이지 호출 인자가 아니다.
- 모델 적절성 판단 — 티어별 기준은 9절이 정하고 선택은 세션이 한다.
- 우회 불가능성 — 기준 디렉토리를 벗어나면 fail-open으로 통과한다. 비용·품질 규칙이지 3절 가드레일이 아니다.

## 요구사항

- R1: `PreToolUse`에서 `tool_name`이 `Agent`(또는 `Task`)인 호출만 판정한다. 그 외 도구는 통과.
- R2: `tool_input.model`이 있으면 **값을 보지 않고** 통과한다 — 지정 자체가 상속을 끊고, 모델명을 코드에 박으면 CLI 라인업 변경 때마다 훅이 낡으며 9절이 유일 원본이라는 규칙도 깨진다. **예외는 `inherit` 하나**(대소문자·공백 무시): 모델명이 아니라 "상속하라"는 지시어라 미지정과 결과가 같고, 통과시키면 게이트가 막으려는 상태가 한 단어로 되살아난다. 판정 기준이 어느 모델인가가 아니라 상속을 끊었는가이므로 ADR 005와 충돌하지 않는다.
- R3: `tool_input.subagent_type`의 티어는 **`.agents/agents/<name>.md` frontmatter의 `tier`**에서 읽는다(10절이 정의 파일을 티어 선언의 원본으로 규정하므로, 로스터가 늘어도 훅을 고칠 필요가 없다). 이름은 `[A-Za-z0-9_-]+`만 허용해 경로 조작을 배제한다.
- R4: 티어가 선언돼 있고 `model`이 없으면 **exit 2 + stderr**로 차단한다(gate-reminder와 같은 계열 — Codex 0.145.0에서 실측된 경로). 메시지는 티어 이름, 상속이 일으키는 결과, 9절 표를 읽으라는 지시를 담는다.
- R5: fail-open — 형식 불명 stdin, 정의 부재·판독 실패, `tier` 미선언, 예외는 전부 exit 0 무출력. 게이트 자체의 결함이 작업을 막지 않는다.
- R6: 회귀 테스트가 `.agents/hooks/tier-gate_test.py`로 영속되며, 티어는 **실제 저장소 정의에서** 읽어 검증한다(하드코딩 금지).
- R7: 등록은 `.claude/settings.json`(matcher `Agent`)과 `.codex/config.toml` 인라인(matcher `Agent|Task|spawn_agent`) 양쪽. **등록 shim은 훅 파일을 먼저 확인하고 없으면 exit 0으로 빠진다**(`[ -r "$f" ] || exit 0`) — 기존 훅들의 shim을 그대로 쓰면 파일 부재·권한 실패 시 인터프리터가 exit 2로 죽고, PreToolUse에서 그 값은 **모든 서브에이전트 발행 차단**을 뜻한다(실측: 파일 없음·`chmod 000`·빈 `CLAUDE_PROJECT_DIR` 전부 exit 2). 차단 훅에서만 생기는 위험이라 다른 훅에는 없던 조건이다. Codex의 발행 도구 이름은 실측하지 않았으므로 후보를 함께 걸며, 어긋나면 발화하지 않을 뿐 오차단은 생기지 않는다(ADR 029 fail-open).

## 인터페이스 / 설계 개요

- 입력: stdin JSON(`tool_name`, `tool_input`). 기준 디렉토리는 `CLAUDE_PROJECT_DIR`(부재 시 cwd).
- 출력: 차단 시 stderr 한 단락 + exit 2, 그 외 무출력 exit 0.
- 부수 효과 없음 — 에이전트 정의 파일 읽기뿐(frontmatter 4KiB만).

## 미해결 질문

- **Codex 발행 도구 이름 미실측** — 매처 후보 3종을 걸었으나 어느 것이 실제인지 확인하지 않았다. Codex 런타임 판정은 이 세션의 몫이 아니며(ADR 031 계약), 어긋나도 fail-open이라 손해는 "Codex에서 게이트가 안 걸린다"에 그친다.
- **matcher `Agent`의 실발화 미관측** — 실측 프로브는 matcher `Task`로 걸어 확인했고(그때 `tool_name`은 `Agent`), 등록은 `Agent`로 했다. 문서가 정확한 이름으로 `Agent`를 지목하고 payload의 `tool_name`도 그 값이라 근거는 충분하지만, `Agent` 매처 자체의 발화를 본 것은 아니다.
- **실효 관측 미완** — 이 훅이 실제로 미지정 발행을 줄이는지는 등록 이후의 세션에서만 확인된다. 다음 주간 점검에서 같은 집계를 다시 내어 미지정 비율을 비교한다.
