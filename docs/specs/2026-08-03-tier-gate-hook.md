# 스펙: tier-gate 훅 — 서브에이전트 발행의 9절 경량 모델 금지 강제

- 날짜: 2026-08-03(신설) / 2026-08-04(판정 반전) / 상태: 구현됨
- 관련: **ADR 040**(현재 결정 — 판정 반전), **ADR 037**(신설 결정 — 판정 방향은 040이 대체), 루트 AGENTS.md 9절(티어→모델 매핑·경량 금지), 10절(에이전트 정의 tier 필드), ADR 005(탈모델명), ADR 012(REGISTRY.md가 설치처 판정 입력이라는 선례), ADR 023·028·029(게이트 실행 계층 승격 선례·Codex 파리티)

## 배경

9절은 티어별 모델을 규정하지만 **적용은 발행 시점의 `model` 파라미터로만 이뤄진다** — 지정하지 않으면 서브에이전트가 부모 세션 모델을 그대로 상속한다. 그래서 이 표는 선언된 이래 한 번도 적용된 적이 없고, 세션 모델이 무엇이냐에 따라 **어느 티어가 위반 상태인지만 뒤바뀌었다.**

실측(2026-08-03, 이 설치처 로컬 세션 로그 `~/.claude/projects/<루트>/*/subagents/*.jsonl`):

| 구간 | explorer(explore 티어) | design 티어(reviewer 등) |
|---|---|---|
| ~2026-07-22 | 표준 11 / 상위 4 (대체로 준수) | **표준 25 / 상위 11 — 검증 25건이 저성능 모델** |
| 2026-07-25~ | **상위 21 / 표준 3 — 역전** | 상위(우연히 준수) |

수치는 세션이 쌓이면 늘어나는 **상태 의존값**이며 위 값은 2026-08-03 집계다. 재현되는 것은 개별 숫자가 아니라 **구간 간 역전과 그 단일 원인**이다.

### 왜 판정을 반전했나 (2026-08-04)

초판(ADR 037)은 이 원인을 **`model` 미지정**으로 보고 미지정 발행을 차단했다. 그 처방이 위험을 역전시켰다.

1. **상속은 경량 등급에 닿을 수 없다.** 세션 모델은 상위·표준 둘 중 하나이므로, 사용자 전역 정책이 **절대 금지**한 상태(검증을 경량 모델로)는 상속 경로에서 구조적으로 발생하지 않는다.
2. **명시 지정을 강제하면 그 경로가 처음 열린다.** 초판은 값을 판정하지 않기로 했으므로(ADR 037 결정표) 경량을 골라도 통과했다.
3. **즉시 실현됐다.** 훅이 신설된 2026-08-03, 수집 목적 발행이 차단됐고 훅 메시지의 지시("9절 표에서 기준을 읽고 골라 지정하라")를 따라 재발행된 것이 **경량 모델 발행**이었다. 사용자가 잡아냈다. 게이트가 막은 위반이 아니라 **게이트가 유도한** 위반이다.
4. **초판은 자기 근거도 막지 못한다.** 위 표에서 더 무겁다고 지목한 "검증 25건이 표준 모델"은 design 티어에 표준 모델을 **지정한** 상태라, 지정 여부만 보는 게이트를 그대로 통과한다. 초판이 실제로 고친 것은 07-25 이후 구간의 explore 과소모(비용)뿐이었다.

그래서 축을 나눴다 — **과소모(비용)는 문서 규칙으로, 경량 검증(정확성)은 실행 계층으로.** 과소모는 재작업을 부르지 않지만 검증의 false negative는 부른다.

문서 규칙만으로는 안 된다는 근거는 그대로 유효하다: 9절은 처음부터 이 표를 갖고 있었고 상속이 늘 이겼다. 반면 **에이전트 타입**은 2026-07-17에 리마인더 훅 문구로 처방한 뒤 37건 전부 explorer로 유지됐다 — 발행 지점에 놓인 장치는 버텼다. **바뀐 것은 처방 위치가 아니라 그 자리에서 무엇을 보는가다.**

## 목표

- 티어가 선언된 에이전트를 **REGISTRY.md 「경량 모델」 절이 나열한 등급으로** 발행하면 **차단**한다.
- **`model` 미지정은 통과**시킨다 — 상속은 안전한 기본값이고, 사용자 전역 정책의 기본값이기도 하다.
- 모델명은 **훅 코드가 아니라 미추적 설치처 데이터**에 둔다(ADR 005).
- 사용자가 명시적으로 "빠르게/가볍게"를 요청한 경우 `[light-ok]`로 통과시킨다(9절 예외의 실행 표현). **`design` 티어는 제외** — 그 금지는 사용자 요청으로 풀리지 않는 별개 조항이다.
- 하네스 로스터 밖, 절 부재, 판독 실패는 통과시킨다(fail-open).

## 비목표

- **티어 적합성 판정** — design 티어를 표준 모델로 발행해도 막지 않는다. 이 훅이 막는 것은 전역 정책이 절대 금지로 못박은 한 등급뿐이고, 나머지 컬럼은 9절을 읽는 세션이 판단한다. **초판에서는 이것이 「한계」였으나 ADR 040에서 의도된 범위로 재규정됐다.**
- **explore 과소모 차단** — 미지정 통과의 대가로 되살아난다. 9절 표와 orchestrate가 규칙으로 관장한다.
- **추론 등급 강제** — Claude Code의 Agent 도구는 `effort` 파라미터를 노출하지 않는다(실측 2026-08-03: `tool_input` 키는 `description`·`prompt`·`subagent_type`·`model`·`run_in_background`). 서브에이전트는 부모 세션 등급을 상속하며, payload 최상위의 `effort`는 그 상속값이 기록된 것이지 호출 인자가 아니다.
- **우회 불가능성** — 기준 디렉토리를 벗어나거나 로스터 밖 타입을 쓰면 통과한다. 비용·품질 규칙이지 3절 가드레일이 아니다.

## 요구사항

- R1: `PreToolUse`에서 `tool_name`이 `Agent`(또는 `Task`)인 호출만 판정한다. 그 외 도구는 통과.
- R2: **`tool_input.model`이 없으면 통과한다.** 미지정은 부모 세션 모델 상속이고, 로스터 에이전트는 자기 모델을 박지 않으므로 그 경로가 경량 등급에 닿지 않는다. `inherit`에는 **분기를 두지 않는다** — 경량 목록에 없는 문자열이라 일반 경로로 통과하며, 따로 처리하면 죽은 분기가 된다(초판에서는 차단 대상이라 분기가 필요했다).
- R3: `tool_input.prompt`에 `[light-ok]`가 있으면 통과한다 — 9절 경량 예외(사용자 명시 요청)를 옮긴 것이다. **단 `design` 티어에는 닿지 않는다**: 사용자 전역 정책은 조항이 둘이고, 경량 예외와 **별도로** 검증·리뷰·최종 확인의 경량 사용을 절대 금지한다(에이전트 정의들도 예외 없이 그렇게 적혀 있다). 그래서 **우회 판정은 티어를 읽은 뒤에** 한다 — 앞에 두면 절대 금지가 표식 한 단어로 풀린다. 표식을 넣는 주체가 게이트 대상이라 기계적 보증은 아니며, 값은 우회가 기록으로 남는 것이다.
- R4: `tool_input.subagent_type`의 티어는 **`.agents/agents/<name>.md` frontmatter의 `tier`**에서 읽는다(10절이 정의 파일을 티어 선언의 원본으로 규정하므로, 로스터가 늘어도 훅을 고칠 필요가 없다). 이름은 `[A-Za-z0-9_-]+`만 허용해 경로 조작을 배제한다. 티어 미선언·판독 실패는 통과.
- R5: 경량 목록은 **REGISTRY.md 「경량 모델」 절의 굵은 라벨 목록**에서 읽는다(`_common.read_lightweight_models`). 판정은 **소문자 + 영숫자 낱말 경계** — 별칭(`haiku`)과 전체 모델 ID(`claude-haiku-4-5-20251001`)를 한 항목이 함께 잡으면서, 낱말 내부의 우연한 일치는 배제한다. 맨 부분 문자열이면 다른 벤더 등급명을 오차단한다(항목 `mini`가 `gemini-2.5-pro`를 막고, 한 글자 항목이 전 발행을 막는다). **빈 항목은 판독기가 걸러낸다** — 집합에 들어가면 어떤 모델에도 매칭돼 fail-open이 fail-closed로 뒤집힌다. **모델명을 훅 코드에 박지 않는 이유는 ADR 005**이며, 설치처 데이터에 두면 판정하면서도 탈모델명이 유지된다(프로필 판독이 쓰는 것과 같은 구조 — ADR 012).
- R6: 티어가 선언돼 있고 지정된 모델이 목록에 걸리면 **exit 2 + stderr**로 차단한다. 메시지는 티어 이름, 지정된 모델, 걸린 목록 항목, **미지정으로 재발행하는 것이 기본값이라는 안내**, `[light-ok]` 우회를 담는다.
- R7: fail-open — 형식 불명 stdin, 정의 부재·판독 실패, `tier` 미선언, **「경량 모델」 절 부재**, 예외는 전부 exit 0 무출력.
- R8: 판독 순서는 **`model` 유무 → 파일 판독(티어·목록) → 경량 매칭 → 우회 판정**이다. `model`을 지정하지 않은 발행이 압도적이므로 매 발행마다 파일을 읽지는 않는다. **우회 판정이 마지막인 것은 성능이 아니라 정확성 때문이다** — 티어를 알기 전에는 그 표식이 닿아도 되는 발행인지 판단할 수 없다(R3).
- R9: 절 판독기는 `_common.py`에 두고 `read_profile`과 **절 파서를 공유한다**(코드 펜스·제목 레벨 처리). 사본을 두면 독립 검증이 잡은 그 수정들을 양쪽에 따로 반영해야 한다.
- R10: 회귀 테스트가 `.agents/hooks/tier-gate_test.py`로 영속되며, **티어도 경량 목록도 실제 저장소에서 읽어** 검증한다(하드코딩 금지).
- R11: 등록은 `.claude/settings.json`(matcher `Agent`)과 `.codex/config.toml` 인라인(matcher `Agent|Task|spawn_agent`) 양쪽. **등록 shim은 훅 파일을 먼저 확인하고 없으면 exit 0으로 빠진다**(`[ -r "$f" ] || exit 0`) — 기존 훅들의 shim을 그대로 쓰면 파일 부재·권한 실패 시 인터프리터가 exit 2로 죽고, PreToolUse에서 그 값은 **모든 서브에이전트 발행 차단**을 뜻한다(실측: 파일 없음·`chmod 000`·빈 `CLAUDE_PROJECT_DIR` 전부 exit 2).
- R12: `harness-install`이 설치 인터뷰에서 「경량 모델」 절을 채우고, 채우지 않으면 **훅이 발화하지 않는다는 결과를 사용자에게 말한다.**
- R13: 판정 입력이 gitignore 대상이라 지워지거나 비어도 `git status`에 흔적이 없다. `integrity-check` **R20**이 그 상태를 주간 점검 출력에 드러낸다 — 항목이 있으면 PASS, 없으면 **SKIP**(FAIL이 아니다: 안 채운 설치처는 설계된 상태이고, FAIL이면 새 설치처가 무결성 실패로 시작한다).

## 인터페이스 / 설계 개요

- 입력: stdin JSON(`tool_name`, `tool_input`). 기준 디렉토리는 `CLAUDE_PROJECT_DIR`(부재 시 cwd).
- 판정 입력 2종: `.agents/agents/<name>.md`(티어), `REGISTRY.md` 「경량 모델」 절(등급 이름).
- 출력: 차단 시 stderr 한 단락 + exit 2, 그 외 무출력 exit 0.
- 부수 효과 없음 — 파일 읽기뿐(frontmatter 4KiB + REGISTRY.md).

## 미해결 질문

- **Codex 발행 도구 이름 미실측** — 매처 후보 3종을 걸었으나 어느 것이 실제인지 확인하지 않았다. Codex 런타임 판정은 이 세션의 몫이 아니며(ADR 031 계약), 어긋나도 fail-open이라 손해는 "Codex에서 게이트가 안 걸린다"에 그친다.
- **차단 경로의 실환경 관측** — 반전 후의 차단(경량 지정)은 stdin 실행으로만 확인했다. 실제 세션에서 경량을 지정할 일이 드물어(그것이 목적이다) 관측 기회 자체가 적다.
- **explore 과소모의 재발 규모** — 미지정 통과로 되살아나는 상태이며, 다음 주간 점검에서 같은 집계를 다시 내어 비교한다.
