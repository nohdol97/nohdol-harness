# Paperclip 자율 개발 판단

## 목표와 범위
사용자가 맡긴 목표 안의 되돌릴 수 있는 개발 결정을 Paperclip 에이전트가 직접 처리한다. Paperclip 전용 계약과 생성 지침에 적용하며 일반 CLI의 인터뷰 규칙은 이번 변경 범위가 아니다. 원본 역할·스킬 본문, 검토 품질, 설치 권한과 기존 업무는 보존한다.

## 요구사항과 완료 기준
- R1/C1: 검증된 Paperclip 실행에서 사전 인터뷰 기본값·사용자 스펙 확정을 전용 자율 판단 규칙으로 대체한다. coordinator가 범위 안의 스펙·완료 기준을 확정하고 구현·테스트·독립 검토까지 진행한다.
- R2/C2: 자료를 먼저 조사하고 기존 패턴으로 구현·파일 배치·테스트 등 가역적 결정을 내린다. 작업자는 기술 질문을 coordinator에게 전달하고 coordinator는 일상적 판단을 사용자에게 재전달하지 않는다. 가정·선택과 근거는 이슈에 기록한다.
- R3/C3: 목표·완료 의미를 크게 바꾸는 충돌, 조사로 확보할 수 없는 필수 사실·자료, 명시적으로 유보된 결정과 권한·파괴적 변경·반출 경계는 필요한 질문만 묶어 요청한다. 영향 없는 작업은 계속하고, 같은 정보가 바뀌지 않으면 질문을 반복하지 않는다. 자격 증명이나 대상 산출물을 추측하지 않는다.
- R4/C4: 인간 질문과 에이전트 검토를 구분한다. review stage를 없애거나 자동 PASS하지 않고 기존 pending 질문·승인도 임의 응답/취소하지 않는다. 에이전트 재개·새 업무 실행·모델 호출은 설치 검증에서 수행하지 않는다.
- R5/C5: 재동기화 후 관리자·역할7개·스킬 사본에 같은 우선순위를 적용하고 원본·모델·권한·상태 설정과 개인정보 설정을 보존한다. 기존 업무 정책의 자동 변경은 하지 않는다. 실행 중 에이전트는 덮어쓰지 않는다.

## 검증
기존 규칙의 사례 판단 baseline → 변경 → 동일 사례와 부정 사례 독립 검토. sync 모의 회귀로 생성 지침의 전달·기존 설정 보존을 검증한다. 실제 설치는 계획 후 동기화하고 API/파일로 확인한다. 외부 push는 하지 않는다.

## 기록
사용자는 반복 질문을 줄이고 Paperclip도 자율적으로 진행하도록 명시 요청했다. 조사한 현재 지침에는 사용자 스펙 확정·불확실하면 인터뷰 기본값이 남아 있어 전용 우선순위를 추가한다. 지식 소스 index는 읽기 timeout으로 참고하지 못했다. 상세 검증은 아래에 기록한다.

## 완료 기록
- C1–C4: 변경 전 가역적 설계 사례에서 사용자 확정 요구 확인, 변경 후 동일 사례 자율 판단 및 필수 APK·파괴적 migration 부정 사례 독립 검토 PASS. 생성 안내 회귀 RED→GREEN, 작성자·독립 검토자 sync 테스트 각각 16/16 PASS. 실제 모델의 무인 실행을 검증한 것은 아니다.
- C5: 관리자1·역할7·스킬19의 설치 지침 반영, 재계획 변경0. 병행 수정 중인 공용 원본과 충돌하지 않도록 이번 설치는 기존 사본의 원문을 보존하고 전용 안내/runtime만 갱신했다. 관리자 바깥 블록·모델/권한/runtime 설정·에이전트 상태 보존 확인. 기존 역할7·스킬19의 원문 대조 및 개인정보 설정4개 해시 동일. 실제 업무·pending 질문·승인·모델 호출·resume 없음.
- 독립 검토 첫 담당의 사용 한도로 대체 검토자를 통해 최종 검토 완료. 설치 기록·rollback 사본·검증은 미추적 `_workspace/paperclip-autonomy/`에 있다. 다중 지침 갱신은 단일 트랜잭션이 아니며 실행 중 에이전트를 갱신하지 않는다. 이번 사전/사후 상태 검사에는 충돌이 없었다. 일반 CLI 정책의 별도 병행 변경은 이 커밋에 포함하지 않는다.
