# Paseo 안의 Paperclip 패널

## 배경과 목표
폰과 데스크톱의 Paseo에서 로컬 Paperclip 업무를 확인하고 등록한다. 화면 조작은 로컬 API를 직접 호출하며 LLM을 거치지 않는다. 기존 하네스 연동의 배포 자산으로 관리한다.

## 요구사항
- R1: Paseo 0.11.2의 클라이언트·서버 플러그인으로 구현한다. 사이드바 화면과 워크스페이스 패널에서 같은 UI를 제공하고 React Native 구성 요소로 모바일을 지원한다.
- R2: 회사 선택, 프로젝트 선택, 이슈 목록·상세·댓글 조회, 에이전트 상태, 최근 실행 상태를 제공한다. 빈 상태·오류·다시 시도·로딩을 표시하고 회사 전환 시 이전 회사 데이터를 지운다.
- R3: 이슈 작성은 프로젝트를 선택한 **미배정 backlog 초안**만 허용한다. 제목·본문 길이와 ID를 서버에서 검증하고 다른 회사의 프로젝트를 거부한다. 제출 중 중복 클릭을 막고 실패 시 입력을 보존한다. 새 초안이 실제 실행을 시작하지 않는지 설치 소스를 확인한다.
- R4: 에이전트 일시 정지만 명시적인 사용자 확인 후 제공한다. 재개·실행·배정·댓글 작성·상태 변경·승인·삭제는 이 버전에 넣지 않는다. 현재 모델 호출 재개 여부가 미결정이기 때문이다. 실제 업무에 시험 초안을 만들거나 에이전트를 변경하지 않고 모의 서버로 쓰기 경로를 검증한다.
- R5: 클라이언트는 Paseo RPC만 사용한다. 데몬 서버는 고정된 `http://127.0.0.1:3100/api`만 호출한다. 임의 URL·경로·HTTP 메서드를 받지 않으며 리디렉션·프록시·무제한 응답·무제한 대기를 차단한다. 외부 통계·폰트·오류 전송·자동 모델 호출을 추가하지 않는다.
- R6: 반환 데이터는 화면에 필요한 필드만 선별하고 agent config·환경 변수·토큰·원시 실행 로그를 내보내지 않는다. 제목·설명·댓글은 실행하지 않는 일반 텍스트다. RPC 요청의 모든 ID는 검증하며 회사 소속을 확인한다.
- R7: 현재 Paperclip local_trusted·loopback·privacy 설정·실행 상태를 보존한다. 이전 기록은 8개 paused였지만 작업 전 조회에서 7개 paused·관리자 running·이슈 7개로 확인됐다. 플러그인 검증 때문에 이를 되돌리지 않는다. 플러그인 설치 시 기존 Paseo 플러그인과 연결 설정을 보존한다. 전역 플러그인 활성화가 다른 플러그인을 가동하지 않는지 확인한다. 원격 접속 경로는 사용자 응답에 따라 별도 적용한다. Git push는 수행하지 않는다.

## 완료 기준
- [x] C1: 조회·초안 등록·정지 RPC의 계약, 회사 경계, 잘못된 입력, 리디렉션, 서버 오류, 시간 초과에 대한 테스트 통과.
- [x] C2: 타입 검사와 Paseo 실제 플러그인 컴파일·실행 성공. 실제 API 조회로 현재 프로젝트·에이전트 상태를 확인.
- [x] C3: 실제 화면에서 목록·상세·빈 상태·좁은 폭을 확인. 실제 폰 테스트가 불가능하면 별도로 명시.
- [x] C4: 등록·정지를 모의 서버에서 검증하고 실제 업무에 쓰기 요청을 하지 않았음을 확인. 동시 사용에 따른 상태 변화와 플러그인 동작을 구별하며 개인정보 설정을 보존.
- [x] C5: 독립 검토와 하네스 무결성 검사, 운영 안내, 변경 이력 완료.

## 비목표
Paperclip 전체 UI 복제, 새 작업 스케줄러, 모델 실행 재개, 공개 인터넷 포트 개방, 사내 VPN 구축은 포함하지 않는다. Paseo의 기존 전송 채널을 플러그인 자체가 대체하지 않는다. 로컬 프로세스 사용자를 신뢰하는 Paperclip 배포 모드를 전제로 하며, 다중 사용자 권한 격리를 주장하지 않는다.

## 접속 경로 결정
사용자는 기존 Paseo 암호화 릴레이 유지를 선택했다. 플러그인 활성화 외에 데몬·릴레이·인증 설정을 바꾸지 않는다. 연결 메타데이터가 운영사에 보이는 성질은 유지되며, 패널 자체의 모델 호출·운영사 통계 전송은 추가하지 않는다.

## 검증 기록
Paseo 0.11.2에서 `nohdol-paperclip-panel`을 로컬 디렉터리 플러그인으로 설치하고 실행·재적재 성공을 확인했다. 전역 플러그인 기능은 활성화했으며 등록된 사용자 플러그인은 이 패널 하나다. 내장 플러그인은 이 스위치와 무관하게 기존부터 실행되는 소스 구조를 확인했다. 데몬을 재시작하지 않았고 릴레이 등 나머지 설정은 보존했다.

독립 검토의 `npm test && npm run typecheck`: 13개 테스트 통과, 타입 오류 없음, 소스 검토 PASS. `python3 -B .agents/hooks/integrity-check.py`: 53 pass / 0 fail. 실제 Paseo RPC를 통해 회사 1·프로젝트 9·에이전트 8·실행 30개, 이슈 상세·댓글을 조회했고 잘못된 ID 입력이 거부됐다.

설치된 Paseo 웹 클라이언트를 로컬 파일로 제공하고 외부 HTTP 요청을 차단한 Playwright 환경에서 실제 데몬에 연결했다. 넓은 화면의 목록·상세, 빈 프로젝트, 프로젝트 미선택 시 초안 제출 차단, 정지 확인 후 취소, 최근 실행, 390px 화면의 사이드바 진입·목록 대신 상세 표시를 확인했다. 브라우저에서만 RPC 연결 오류를 주입하고 다시 시도로 실제 보드가 복구됨을 확인했다. 원본 코드에는 테스트 우회나 오류 주입이 없다. 실물 iOS/Android 기기 및 실제 릴레이 경유 접속은 시험하지 않았다.

등록·정지 테스트는 모의 서버만 사용했고 실제 업무에는 쓰기 요청을 보내지 않았다. 작업 중 기존 관리자가 running에서 idle로 바뀌고 다른 역할·업무도 달라져, 예전 pause 스냅샷을 복원하지 않았다. Paperclip config·env·LaunchAgent 파일 해시는 동일했다. 원시 증거·화면은 미추적 `_workspace/paseo-paperclip-panel/`에 보관하며 원격 Git 전송은 하지 않는다.
