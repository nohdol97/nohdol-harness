# ADR 032 — 토큰 효율형 오케스트레이션

- **날짜**: 2026-07-25
- **상태**: 활성
- **관련**: ADR 010·013·016·021·026, 스펙 `2026-07-25-token-efficiency-contract`

## 변경 내용

1. 필수 검증을 먼저 확보한 뒤 작업별 Agent 호출 예산을 세우고, 같은 역할·관점의 후속 검증은 기존 에이전트에 델타로 재요청한다.
2. 자동 주입 문서와 이미 읽은 파일은 다시 전문 로드하지 않고, 변경된 입력과 증거만 델타 패킷으로 전달한다.
3. 작업 단위가 끝난 시점에 컨텍스트가 약 150k를 넘으면 구조화된 이월 후 새 세션을 권고한다.
4. 원시 로그는 작업 공간에 두고 에이전트와 사용자에게는 결론·증거 포인터·미검증 범위를 기본 반환한다.
5. 스킬 description 합계와 `CLAUDE.md`에 기계 예산을 두되 라우팅·안전·이해도 게이트의 의미 보존을 우선한다.

## 대상

`CLAUDE.md`, `.agents/skills/*/SKILL.md`, `.agents/agents/*.md`, `.agents/hooks/integrity-check.py`, 관련 테스트·문서

## 사유

최근 28일 기록은 서브에이전트 호출과 장기 세션, 반복 재독이 고비용 세션의 주된 증폭 요인임을 보였다. 고정 프롬프트 캐시 적중률은 96.6%여서 문서 축소만으로는 비용 효과가 제한적이다. 반면 에이전트 1회 추가는 독립 모델·도구 작업 전체를 추가하므로, 호출을 재사용하고 결과를 델타로 넘기는 편이 품질을 유지하면서 더 큰 절감 효과를 낸다.

재독 금지(2항)의 비용은 1회분이 아니라 **증폭분**이다. 중복 호출의 출력은 트래젝토리에 남아 이후 턴의 입력으로 재소비되므로 실질 비용의 형태는 `낭비 토큰 × 이후 턴 수`다 — 즉 같은 중복이라도 세션 초반일수록 비싸다. 852턴 세션에서 중복 1건이 336턴을 남기고 발생하면 이 공식으로 약 10만 토큰 규모의 상한이 나온다(2026-07-26 검토: docs/proposals/2026-07-26-clew-review.md). **이 수치는 "이후 모든 턴에 재소비된다"고 가정한 구조적 상한이지 측정된 비용이 아니고**, 산출 근거가 된 중복 자체도 위양성으로 판정됐다 — 근거로 삼는 것은 수치가 아니라 **초반 낭비가 후반보다 비싸다는 비대칭**이다. 이 때문에 델타 패킷은 세션 후반의 절약 기법이 아니라 착수 시점부터 적용해야 한다.

| 문서 로딩 | 자동 주입 루트 규칙은 재독하지 않고 프로젝트별·작업별 문서만 지연 로드 | 항상-온 규칙 보존과 JIT 컨텍스트를 양립시킨다 |

## 한계

- 예상 절감률은 최근 기록에 기반한 추정이며 다음 주간 점검에서 실제 Agent 호출 수와 입출력 토큰을 다시 측정한다.
- 같은 reviewer 재사용은 작성자와 verifier가 동일해지는 자기검증을 허용하지 않는다.
- 150k는 CLI의 강제 컨텍스트 한도가 아니며, 작업 경계에서만 적용되는 운영 임계값이다.
- **이 항목에는 강제 장치가 없다(2026-07-26 추가).** 규칙 적용 커밋(`73c4b68`, 2026-07-25T05:42Z) **이후에 시작된** 세션 **10건 중 임계 초과 4건**(202,910 / 216,110 / 290,518 / 351,848, 전부 07-26), 임계 이하 6건(최대 128,545) — **초과율 40%**. 분모에는 피크 0인 세션도 포함한다(시작만 하고 작업이 없던 세션을 빼면 분모가 자의적이 된다). 07-25의 241,717·228,516은 커밋 **이전** 시작이라 규칙을 적재하지 않았으므로 제외한다. **이 수치는 2026-07-26 시점 스냅샷이며 진행 중 세션은 값이 계속 오르므로, 이후 인용할 때는 재측정한다.** 각 세션에 완료 경계가 실재했는지는 기계로 확인할 수 없어 **위반 단정이 아니며**, 확인된 것은 강제 수단의 부재와 위 초과 빈도다. **사용자 결정(2026-07-26)**: 고지 장치를 신설하지 않고 권고로 유지한다. 장치가 원리적으로 불가능해서가 아니다 — `gate-reminder` 훅이 이미 휴리스틱 조건 위에서 세션당 1회·fail-open으로 동작하는 선례이므로 같은 계열의 경량 고지는 기술적으로 열려 있다. 재검토는 임계 초과가 **실제 손실(이월 실패·재작업)로 이어진 사례가 관측될 때** 하고, **관측 지점은 harness-review 주간 점검(신호 ②·④)**이며, 그때 gate-reminder 계열이 1순위 후보다.
- 고위험 보안·인프라 및 스펙 완료 검증은 비용 예산보다 우선한다.
