# ADR 032 — 토큰 효율형 오케스트레이션

- **날짜**: 2026-07-25
- **상태**: 활성
- **관련**: ADR 010·013·016·021·026, 스펙 `2026-07-25-token-efficiency-contract`

## 변경 내용

1. 필수 검증을 먼저 확보한 뒤 작업별 Agent 호출 예산을 세우고, 같은 역할·관점의 후속 검증은 기존 에이전트에 델타로 재요청한다.
2. 자동 주입 문서와 이미 읽은 파일은 다시 전문 로드하지 않고, 변경된 입력과 증거만 델타 패킷으로 전달한다.
3. 작업 단위가 끝난 시점에 컨텍스트가 약 150k를 넘으면 구조화된 이월 후 새 세션을 권고한다.
4. 원시 로그는 작업 공간에 두고 에이전트와 사용자에게는 결론·증거 포인터·미검증 범위를 기본 반환한다.
5. 스킬 description 합계와 `CLAUDE.md`에 기계 예산을 두되 라우팅·안전·이해도 게이트의 의미 보존을 우선한다.

## 대상

`CLAUDE.md`, `.agents/skills/*/SKILL.md`, `.agents/agents/*.md`, `.agents/hooks/integrity-check.py`, 관련 테스트·문서

## 사유

최근 28일 기록은 서브에이전트 호출과 장기 세션, 반복 재독이 고비용 세션의 주된 증폭 요인임을 보였다. 고정 프롬프트 캐시 적중률은 96.6%여서 문서 축소만으로는 비용 효과가 제한적이다. 반면 에이전트 1회 추가는 독립 모델·도구 작업 전체를 추가하므로, 호출을 재사용하고 결과를 델타로 넘기는 편이 품질을 유지하면서 더 큰 절감 효과를 낸다.

## 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 호출 제어 | 하드 전역 상한이 아니라 Phase 0 예상 예산 + 새 위험 축 승격 | 큰 작업의 필수 관점을 막지 않으면서 중복 발행을 드러낸다 |
| 재검증 | 동일 reviewer 후속 턴에 변경 diff·테스트만 전달 | 독립성은 작성자와 verifier 분리에서 오며, 같은 verifier 재사용은 판단 기준의 일관성과 입력 절감을 함께 준다 |
| 문서 로딩 | 자동 주입 루트 규칙은 재독하지 않고 프로젝트별·작업별 문서만 지연 로드 | 항상-온 규칙 보존과 JIT 컨텍스트를 양립시킨다 |
| 세션 교체 | 약 150k + 완료 경계에서 권고 | 진행 중 강제 교체의 이월 손실을 피하면서 context rot 구간을 줄인다 |
| 출력 | 상세는 파일, 반환은 요약·포인터 | 원시 로그가 주 컨텍스트에 중복 적재되는 것을 막는다 |
| 고정 입력 | 스킬 설명 합계 9,000B, `CLAUDE.md` 5,500B | 현재 13.7KB·8.7KB에서 의미 보존형 감량을 강제하되 지나친 단문화를 피한다 |

## 한계

- 예상 절감률은 최근 기록에 기반한 추정이며 다음 주간 점검에서 실제 Agent 호출 수와 입출력 토큰을 다시 측정한다.
- 같은 reviewer 재사용은 작성자와 verifier가 동일해지는 자기검증을 허용하지 않는다.
- 150k는 CLI의 강제 컨텍스트 한도가 아니며, 작업 경계에서만 적용되는 운영 임계값이다.
- 고위험 보안·인프라 및 스펙 완료 검증은 비용 예산보다 우선한다.
