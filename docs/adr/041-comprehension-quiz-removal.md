# ADR 041 — PR 전 이해도 퀴즈 게이트 제거

- **날짜**: 2026-08-04
- **상태**: 활성
- **관련**: AGENTS.md 13절(서두 원칙·0항)·5절(루트 원격 PR 사이클), `branch-workflow` 마무리 절차, `orchestrate` 검증 필수 문단, `team-review` Phase 0, ADR 038(사내 프로필 검증 면제 — 퀴즈 실행 지점을 분기시키던 조항), 스펙 `2026-07-25-token-efficiency-contract`(R5·R7)

## 변경 내용

1. **`branch-workflow` 마무리 4단계(이해도 퀴즈 게이트)를 통째로 삭제한다.** 그 단계가 퀴즈 스펙의 단일 원본이었으므로 스펙 전체 — 실행 지점, 분기 ⓐⓑⓒ, 품질 바 ①~⑤, 위험 축 분량 규칙, 보완 질문 리스트, 오답 = 불일치 신호 — 가 함께 사라진다. 이후 단계는 4(PR 생성)·5(사용자 머지)로 번호를 당긴다.
2. **퀴즈를 실행시키던 두 지점을 제거한다** — `orchestrate` 검증 필수 문단의 「리뷰 창 퀴즈」와 `team-review` Phase 0의 같은 문단. 백그라운드 리뷰 발행은 그대로이며, 없어지는 것은 그 대기 시간에 퀴즈를 병렬로 태우던 의무뿐이다.
3. **13절 서두의 최상위 원칙은 남기되 강제 장치가 없다는 사실을 조항 안에 적는다.** 「사용자 이해는 완료의 요건」과 그것이 요구하는 리포트 내용(결정 갈림길 교습 + diff 읽기 가이드)은 유지하고, **무엇도 이것을 붙잡지 않는다는 것이 결정임을** 명시한다. 빈약한 리포트는 지적할 결함이지 PR 차단 사유가 아니다.
4. **5절 루트 원격 PR 사이클의 "퀴즈 없음" 괄호를 뺀다.** 면제할 게이트가 없어졌으므로 면제 문구가 남으면 존재하지 않는 규칙을 가리킨다.
5. 13절 0항의 "자율 결정을 보고와 **퀴즈에서** 회수한다"를 보고 단독으로 좁힌다. 인터뷰 우선 규칙 자체는 무변경이다.
6. 상시 노출 계약(스펙 R5·R7)에서 퀴즈 항목을 빼고 회귀 테스트 두 곳의 단언을 교체한다 — R5의 완료 답변 확장 예외 목록, R7이 `CLAUDE.md`에 유지시키던 「이해 전달 게이트」.
7. 한글 뷰 3종(`AGENTS.ko.md`, `.agents/skills/README.ko.md`)과 단계 번호 참조 4곳(`reviewer.md`, `team-review`, `orchestrate`, `docs/README.md`)을 동조한다. `metaskill` 공통 규칙 8의 베이스라인 인용은 사라진 단계 번호 대신 그 단계의 이름으로 다시 적는다.

## 대상

`AGENTS.md`(5절·13절 서두·13-0), `CLAUDE.md`(사용자 이해 앵커), `AGENTS.ko.md`, `.agents/skills/branch-workflow/SKILL.md`(description + 마무리 4단계 삭제 + 번호 재정렬), `.agents/skills/orchestrate/SKILL.md`, `.agents/skills/team-review/SKILL.md`, `.agents/skills/metaskill/SKILL.md`(공통 규칙 8 인용), `.agents/skills/README.ko.md`, `.agents/agents/reviewer.md`, `.agents/hooks/token-efficiency-contract_test.py`, `docs/specs/2026-07-25-token-efficiency-contract.md`, `docs/README.md`, `docs/harness-changelog.md`, `docs/adr/041-comprehension-quiz-removal.md`(이 파일)

## 사유

**사용자 판정**(2026-08-04): "이 하네스 PR 전에 퀴즈를 내는데, 형편 없어서 제거하려고 해."

게이트를 운영하는 쪽에서 보면 이 판정은 이미 기록에 예고돼 있었다. 실측: `72440a6` 시점 `docs/harness-changelog.md`에서 「퀴즈」를 담은 이력 행은 **15행**이고, 그중 **퀴즈 장치 자체가 주제인 행은 7행**이다(2026-07-25 신설, 07-25 실행 지점 이동, 07-26 품질 기준 4항 신설, 07-26 분량 위험 축 재정의, 08-02 루트 확장, 08-02 그 확장 철회, 08-02 품질 바 ⑤ 신설). **9일 사이 7번 고쳤고, 그중 4번의 사유 칸이 사용자 지적·사용자 결정이다**(07-26 두 행, 08-02 철회 행, 08-02 ⑤ 행). 장치가 수렴하지 않고 매번 사용자가 결함을 발견해 주는 쪽으로 굴러갔다는 뜻이다.

무엇이 반복해서 어긋났는지도 한 방향이다. 07-26 품질 기준 4항은 **자명 문항**(건네준 리포트만 보고 맞힐 수 있는 문항)을 막으려 신설됐고, 08-02 품질 바 ⑤는 반대로 **사용자가 닿을 수 없는 곳에 근거가 있는 문항**을 막으려 신설됐다. 두 상한 사이에 남는 폭이 "diff가 실제로 가르는 구간"인데, 그 구간을 조준하는 문항을 매번 만들어 내는 것이 이 장치의 실행 비용이었고 — 두 번의 사용자 지적이 말해 주듯 — 자주 실패했다. 08-02 루트 확장이 **같은 날 철회**된 것도 첫 적용에서 사용자가 답할 수 없는 문항이 나왔기 때문이다.

**대체 장치를 두지 않는 것도 결정이다.** 초안 단계에서 "핵심적인 것을 vault에 문서화"를 대체 의무로 놓는 안이 검토됐으나 사용자가 "그냥 퀴즈만 삭제하자"로 범위를 좁혔다. 따라서 13절의 이해 요건을 붙잡는 단계는 이제 없다 — 남는 것은 리포트 내용(결정 공간 교습, diff 읽기 가이드)뿐이며, 그것은 §16이 말하는 값싼 리포트 추가이지 게이트가 아니다. **이 사실을 13절 조항 안에 명시적으로 적었다.** 그러지 않으면 다음 주간 무결성 점검이 "§13의 이해 요건에 강제 장치가 없다"를 결함으로 다시 올리고, 2026-08-02에 이미 한 번 있었던 발견-재개봉 왕복이 반복된다(그때는 반대 방향이었다 — 점검이 "퀴즈가 루트에 도달 못 한다"를 2주 연속 올렸고, 그 답이 명시적 면제 문구였다).

**남기는 것과 지우는 것의 경계**: 실행되는 문서에서는 지우고, 읽히는 역사에서는 남긴다. ADR·changelog·proposals의 퀴즈 서술은 시점 기록이므로 그대로 두며(6절), `vault-write`와 `.agents/skills/README.ko.md`가 "2026-07-28 이해도 퀴즈 오답이 이 결함을 드러냈다"고 적은 두 곳도 **증거 출처**라 유지한다 — 장치가 사라져도 그 사건이 일어났다는 사실은 바뀌지 않고, 지우면 그 규칙의 근거가 사라진다.

## 영향

- **잃는 것**: PR 전에 사용자의 오해를 검출하던 유일한 지점. 앞으로 불일치는 PR 본문·리포트를 사용자가 읽다가 발견하거나, 머지 후에 드러난다. 13절의 나머지 절반(§13-2 정확성 증거·독립 검증)은 무변경이므로 **작업물의 정확성 보증은 줄지 않는다** — 줄어드는 것은 사용자 이해 쪽 확인뿐이다.
- **얻는 것**: PR 직전 라운드 1~2회(문항 작성·해설·보완 질문 리스트)와 그것을 지탱하던 스펙 4,300여 바이트. `branch-workflow` 마무리는 검증 → rebase → 푸시 → PR → 머지의 5단계로 돌아간다.
- **되돌리기**: 이 ADR을 대체하는 ADR + `branch-workflow` 마무리 4단계 복원(이 커밋의 diff가 원본이다). 재도입한다면 **품질 바 ①과 ⑤ 사이 폭을 어떻게 매번 맞출 것인가**가 먼저 답해야 할 질문이며, 그 답 없이 되돌리면 같은 7행이 다시 쌓인다.
- **강제 없는 조항이 하나 남는다**: 13절 서두. 이것이 정상 상태임을 조항 자신이 적고 있으므로 점검은 이 줄로 답한다.
