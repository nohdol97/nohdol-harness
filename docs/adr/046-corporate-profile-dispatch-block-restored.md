# ADR 046 — ADR 045 철회: 사내 프로필의 발행 차단을 되살린다

- **날짜**: 2026-08-07
- **상태**: 활성
- **관련**: [ADR 045](045-corporate-profile-dispatch-restored.md)(**이 ADR이 폐기**), [ADR 042](042-corporate-profile-dispatch-block.md)·[ADR 038](038-corporate-profile-verification-exemption.md)(**둘 다 다시 활성**), ADR 012(설치처 프로필), 스펙 `2026-08-04-dispatch-gate-hook`(다시 구현됨)

## 변경 내용

1. **ADR 045를 철회하고 042·038 상태로 되돌린다.** 커밋 `1b1779f`를 `git revert`로 되돌렸다 — `dispatch-gate.py`와 그 테스트, Claude·Codex 등록, 무결성 R18·R21의 필수 목록, 규칙·스킬·에이전트·한글 뷰의 프로필 분기가 전부 복원됐다. 사내 프로필에서 서브에이전트 발행은 다시 전면 차단이며, `infra-specialist` 하나만 통과하고 우회 표식은 없다.
2. **ADR 045 파일은 남긴다.** §6이 대체된 ADR을 지우지 말라고 하며, 폐기 배너로 상태를 표시했다. 042·038의 상태 줄은 revert로 원래 값(활성 / 부분 대체→042)으로 돌아왔고, 거기에 **이 왕복이 있었다는 한 줄**을 더했다 — 그 줄이 없으면 045 파일만 대체를 주장하고 042는 그런 일이 없었다는 얼굴을 해, 나중에 어느 쪽이 참인지 파일 두 개를 대조해야 한다.
3. **되돌리지 않은 것이 셋 있다 — 전부 045와 무관한 테스트 결함이고, 045를 검증하다 발견됐다.** revert에 딸려 사라졌을 것을 다시 넣었다.
   - `_common_test.py` C4b의 대상 선택을 파일명(`gate` 포함)이 아니라 **`read_profile` 보유 여부**로 바꾸고, 대상이 0이면 실패하는 어서션을 넣었다. 이름 기반이던 동안 `harness-review-reminder`의 폴백 판독기는 **042 시절부터 무검사**였다(그 폴백이 `사내`를 돌려주면 개인 설치처에서 일일 점검이 영구히 억제된다).
   - R18 회귀 케이스의 어서션을 게이트 이름에서 **R18 고유 문구**(`PreToolUse command missing contract: …`)로 고정했다. 이름만 보면 같은 출력의 R20·R21 줄이 대신 충족시켜, `CODEX_HOOK_COMMANDS` 항목을 지우는 변이가 초록으로 통과했다.
   - R21 정상 케이스의 `gate-reminder` 어서션을 **개수(`count == 2`)**로 고정했다. `PreToolUse`·`PostToolUse` 양쪽에 필수라 `assertIn`은 한쪽만 남아도 통과한다.

## 사유

**사용자 판정**(2026-08-07): "롤백하자. 비용 때문에 안 되겠다." ADR 045가 딛고 선 전제(사내에서도 발행 비용을 감당할 수 있게 됐다)가 철회됐으므로, 그 위에 선 결정도 함께 내려온다.

**045가 그날 아침의 판정을 성문화한 것이었듯 이 ADR도 그렇다.** 042가 자신에 대해 적은 문장 — 「위반을 막는 게이트가 아니라 비용 판정의 성문화이며, 사내 설치처의 발행 실패 기록은 이 저장소에 0건이다」 — 은 이 왕복 전체에 그대로 적용된다. 세 ADR(042·045·046)이 뒤집은 것은 관측된 사고가 아니라 **비용을 낼 의사**다. 그러니 다음에 같은 질문이 오면 다투어야 할 것은 규칙의 옳고 그름이 아니라 **그 시점의 비용 감당 여부** 하나다.

**왕복 자체가 남기는 실측치**(이 ADR이 기록하는 주된 값):

| 항목 | 실측 |
|---|---|
| 045가 만진 파일 | 35건(훅 층 8 + 등록 2 + 규칙·스킬·문서 25) |
| 046의 revert가 되돌린 것 | 같은 35건, `git revert` 한 번 |
| 되돌릴 때 손으로 처리한 것 | ADR 045 보존·배너, ADR 046 신설, 042·038 왕복 한 줄, MOC 3행, 변경 이력, 되돌리면 안 되는 테스트 개선 3건 |
| 걸린 검증 | 훅 스위트 9파일 전량, 무결성 55 pass / 0 fail |

즉 **프로필 분기를 넣고 빼는 비용은 대칭이 아니다** — 넣을 때는 분기 문장이 여러 층에 퍼지고, 뺄 때는 revert가 그것을 한 번에 되돌리지만 문서 상태(어느 ADR이 활성인가)는 손으로 정리해야 한다. 앞으로 프로필 분기를 새로 만들 때 이 표를 근거로 쓴다.

## 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 되돌리는 방식 | `git revert 1b1779f` + 문서 층 손 정리 | 기계적 역연산이라 042 상태와의 일치가 diff로 증명된다. 새로 짜면 그 보증이 없다 |
| ADR 045 처리 | 파일 보존 + 폐기 배너 | §6(대체된 ADR 삭제 금지). 왕복 기록이 다음 판단의 입력이다 |
| 042·038 | 다시 활성 — 상태 줄에 왕복 한 줄 추가 | revert가 상태 값을 되돌리지만, 그 사이에 있었던 일은 되돌려지지 않는다 |
| 테스트 개선 3건 | 되돌리지 않는다 | 042 시절부터 있던 결함이고 발행 차단 여부와 무관하다. 롤백에 딸려 보내면 리뷰가 산 것을 버린다 |
| 독립 검증 | 발행하지 않는다(사용자 결정) | 비용이 롤백 사유인데 검증에 같은 비용을 쓰는 것은 모순이다. 대신 아래 「검증」의 인라인 확인을 남긴다 |

## 검증

**독립 검증 없음 — 사용자 결정으로 발행을 생략했다**(비용이 롤백 사유). 메인 루프가 인라인으로 확인한 것은 다음이며, 팬아웃도 독립 검증자도 없었다.

- **복원이 042 상태와 정확히 같은지**: `git diff 020f2ee --stat -- .agents/hooks .agents/skills .agents/agents .claude .codex AGENTS.md AGENTS.ko.md CLAUDE.md README.md` → **변경 파일 2개뿐**(`_common_test.py`, `integrity-check_test.py`)이고 둘 다 위 3항의 테스트 개선이다. 즉 코드·규칙 층에서 042 상태와의 차이는 의도한 3건이 전부다.
- 훅 스위트 **9파일 195건** 전량 OK(`dispatch-gate_test.py` 복귀 포함), `integrity-check` **55 pass / 0 fail / 0 skip**.
- `dispatch-gate` 회귀 **6경로 재실행**(임시 REGISTRY.md, `CLAUDE_PROJECT_DIR`로 주입): `사내`+`reviewer`/`implementer`/타입 미지정 → 전부 exit 2(차단), `사내`+`infra-specialist` → exit 0(예외 통과), `개인`+`reviewer` → exit 0, REGISTRY.md 부재 → exit 0(fail-open 방향이 「발행이 돌아간다」임을 확인).

## 영향

- **되돌아온 것**: ADR 042의 「잃는 것」이 그대로 다시 유효하다 — 사내에서 병렬 수집·독립 검증·관점 팬아웃이 사라지고, 리뷰는 저자가 자기 작업을 보는 것이 되며, 그 사실을 산출물에 적어야 한다. 컨텍스트 위생도 다시 잃는다.
- **되돌아오지 않은 것**: 위 3항의 테스트 개선 3건, 그리고 이 왕복의 기록(045·046·변경 이력 행들).
- **되돌리기**: 이 ADR을 대체하는 ADR + `1b1779f`를 다시 적용(`git cherry-pick`). 045의 diff가 저장소에 남아 있으므로 재적용 비용은 처음보다 낮다.
- **관측되지 않은 채 나간다**: 이 설치처는 `개인`이라 사내 경로가 실환경에서 돈 적이 없다 — 042·038·045가 전부 같은 문장을 적었고, 이 왕복 동안에도 달라지지 않았다.
