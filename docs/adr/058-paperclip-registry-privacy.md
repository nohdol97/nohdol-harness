# ADR 058: Paperclip 로컬 레지스트리와 수집 비활성화

- 날짜: 2026-10-15
- 상태: 활성

## 배경
사용자가 하네스의 레지스트리를 Paperclip에도 반영하고 운영사로 나가는 정보를 차단하도록 요청했다. 설치별 경로·관계·이관 정보를 공유 저장소에 복제하지 않으면서 프로젝트 선택과 작업 규칙을 연결해야 한다.

## 결정
별도 `registry_sync.py`가 로컬 `REGISTRY.md`를 읽어 Paperclip 프로젝트 설명과 workspace metadata로 연결한다. 원본은 이동하거나 수정하지 않는다. API 대상은 기존 동기화와 같은 loopback 제한을 사용한다. 소유권 표식 충돌은 적용 전에 거부하고, 수동 정보·기존 ID를 보존하며 변경 없는 PATCH를 생략한다. 삭제는 동기화 범위에 포함하지 않는다.

실제 Git 루트·HEAD·중앙 규칙을 확인한다. 준비된 제품에는 격리 worktree 정책을 설정하고 준비되지 않은 신규 항목에는 실행 workspace를 만들지 않는다. 기존 workspace의 보존은 작업 가능 판정이 아니다. 원본 재확인과 루트 §7 정지는 실행 계약의 책임이며 이 metadata를 서버 실행 게이트로 표현하지 않는다. 로컬 기준점 확인도 `branch-workflow`의 최신 원격 기준점 검증을 대체하지 않는다.

설치의 telemetry와 update check를 끄고 Sentry·OpenTelemetry 설정을 비활성화한다. 피드백 공유 선호도는 거부로 설정한다. 설치 코드에는 피드백 전송 disable 옵션이 없으며 빈 주소는 운영사 endpoint로 되돌아가므로, 사용하지 않는 loopback 포트로 목적지를 고정한다. 저장소와 백업은 로컬로 유지한다. 설정은 설치 파일에만 적용하고 실행 패키지를 직접 수정하지 않는다.

OpenAI 호출과 명시적으로 연결한 외부 작업 도구는 운영사 telemetry와 구분한다. 외부 작업 통신 허용 여부가 확정되기 전에는 idle 에이전트를 pause하고 모델 테스트·원격 Git 작업을 하지 않는다. 이 설정을 OS 차원의 전체 외부 통신 차단으로 주장하지 않는다.

## 대안과 한계
- 독립 레지스트리 수동 관리: 원본과 달라질 수 있어 제외.
- 제품 저장소에 중앙 규칙 복사: 기존 중앙 관리 구조와 충돌하므로 제외.
- 모든 outbound를 방화벽으로 차단: 모델·연결 도구까지 중지하며 요청 범위가 확정되지 않아 적용하지 않는다.
- 설치 패키지 피드백 코드 직접 수정: 재설치 때 사라질 수 있어 지원 환경 설정을 사용한다. loopback 업로드 실패·재시도 로그는 남을 수 있다.

## 검증
스펙은 `docs/specs/2026-10-15-paperclip-registry-privacy.md`, 운영법은 `.agents/integrations/paperclip/README.md`에 둔다. synthetic fixture 회귀와 로컬 API 적용·재적용, 설치 소스의 설정 해석을 확인한다. 모든 네트워크 경로의 봉쇄나 실제 제품 스펙 완수는 검증 범위가 아니다.
