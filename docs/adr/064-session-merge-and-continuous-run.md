# ADR 064 — 세션 직접 머지와 연속 진행을 모든 프로젝트로 확대

- **날짜**: 2026-11-25
- **상태**: 활성
- **대상**: `AGENTS.md` §3·§5·§7-7·§11·§14, `CLAUDE.md`, `branch-workflow`, `orchestrate`, `work-tracker`, `release`, `wrapup`, 한글 뷰

## 변경 내용

1. **하위 프로젝트 PR은 맡은 세션이 직접 머지한다.** 프로젝트와 설치 프로필을 가리지 않는다. 조건은 `branch-workflow` 「Session merge」가 단일 원본이다. 루트의 "사용자만 머지" 규칙을 대체한다.
2. **CI를 기다리지 않는다.** 머지 직전에 한 번만 읽는다. 대기 중이면 머지하고, 실패했으면 이번 변경과 무관함이 확인될 때만 넘긴다.
3. **연속 진행을 모든 프로젝트에 적용한다.** 이어 가라는 지시면 컨텍스트 약 100k 미만에서 같은 세션이 준비된 다음 작업을 맡는다. 원본은 `orchestrate` 「Completed-task context rotation」이다.
4. **작업 절차에 남은 사내 구분을 없앤다.** 폐기된 "사내 Claude/Codex는 순차 실행" 문구를 지운다.

5. **머지한 세션이 바로 정리한다.** worktree 제거 → 로컬 `main` 빨리감기 → `branch -d` 순서다. 로컬 `main`이 뒤처지면 `branch -d`가 머지된 브랜치를 거부한다(2026-11-25 정리 전 실측: PKI `main`이 518커밋 뒤, 머지된 로컬 브랜치 135개 잔존. 추적 브랜치가 없는 브랜치에서 생긴다).

## 이유

사용자가 "머지도 알아서, CI 무시, 잠정 답안, subagent 활용" 문구를 이어가기 요청마다 붙이고 있었다. 2026-11-21~23의 짧은 PKI 이어가기 세션 여러 건이 머지 대기나 한 단위 완료 뒤 멈췄다. 사용자 결정: "전체 프로젝트, 사내라고 예외 없어. ci 는 기다리지 않음."

## 유지한 것 (잠정 해석)

"사내라고 구분한 부분이 있다면 없애"를 **작업 진행·머지 절차의 구분**으로 해석했다. 아래 사내 제한까지 없애려면 루트 §5 설치 프로필 항목과 `metaskill` 프로필 게이트, 각 스킬의 반출 제한 문구를 바꾸면 된다.

- **§3 확인.** 머지가 운영 배포·DB 마이그레이션·권한 변경을 일으키면 먼저 확인받는다.
- **브랜치 보호와 필수 승인.** `--admin`·`--auto`로 우회하지 않는다.
- **사내 루트 하네스 수정·푸시 금지와 데이터 반출 제한.** 작업 진행 방식의 구분이 아니라 회사 컴퓨터의 내용이 개인 저장소나 외부로 나가는 것을 막는 경계라 남겼다.
- **루트 하네스 원격 세션 PR.** 하위 프로젝트 PR이 아니므로 사용자가 머지한다.

## 한계

- CI만 잡는 결함(다른 OS 등)은 머지 뒤에 드러날 수 있다.
- 독립 리뷰를 실행할 수 없는 세션은 머지하지 못하고 PR을 남긴다.
