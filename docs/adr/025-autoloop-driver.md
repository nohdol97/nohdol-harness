# ADR 025: autoloop — 세션 외부 드라이버 기반 자율 멀티세션 루프

- **날짜**: 2026-07-19
- **변경 내용**: 자율 멀티세션 루프 자산을 신설했다 — `.agents/skills/autoloop/`(발사대 스킬: 최초 start/status/stop 3동사, 관측용 dashboard 추가는 ADR 047) + `scripts/driver.py`(루프 본체: 세션 바깥의 Python 프로세스가 `claude -p` headless를 반복 기동). 반복 간 상태는 `_workspace/autoloop/<작업명>/carryover.md` 핸드오프 노트로 넘기고, 산출물·로그도 같은 디렉토리에 둔다(§4 규약). CLAUDE.md 라우팅 앵커에 트리거("자율 루프"·"무인 실행"·"밤새 돌려줘")를 추가했다.
- **대상**: `.agents/skills/autoloop/`(SKILL.md, scripts/driver.py, scripts/driver_test.py), CLAUDE.md 앵커, docs/specs/2026-07-19-autoloop-driver.md
- **사유**: 한 세션 컨텍스트를 넘는 작업의 무인 완주("wrapup→clear→재개" 자동화)가 필요한데, `/clear`는 CLI 명령이라 세션 안의 모델이 스스로 부를 수 없다. **드라이버를 세션 바깥에 두면 새 프로세스 = 새 컨텍스트**라 clear가 구조적으로 해결된다 — 이 아키텍처 결정(스킬이 본체가 아니라 발사대)이 이 ADR의 핵심이다. 사용자 요청·설계 합의 2026-07-19(목적: 멀티세션 완주 + 자율 개발, 안전 범위: 읽기·편집만 무인).
- **핵심 설계 결정**:
  - **게이트 3종이 존재 조건**: ① 안전 — `acceptEdits` + allow/disallow 목록, 파괴적 작업은 `blocked` 정지 후 사용자 이월(§3 완화 불가, `bypassPermissions` 전면 금지) ② 검증 — 테스트는 드라이버가 독립 실행한 결과만 증거(§13 신선한 증거의 무인 버전), `done` 주장은 읽기 전용 reviewer 검증 반복의 PASS 필수 ③ 정지 — 7종 종료 조건(done/blocked/stalled/exhausted/stopped/cost/error)으로 반드시 유한 종료. 무인 모드는 하네스 소프트 게이트(리뷰·증거)를 침식하므로, 재량이던 검증을 루프 구조의 필수 단계로 승격했다.
  - **불변 앵커로 드리프트 방지**: 매 반복 프롬프트에서 목표(스펙 경로)는 불변이고, 갱신되는 것은 핸드오프 노트·테스트 실측·리뷰 피드백뿐이다 — "프롬프트 자동 개선"을 목표 재작성이 아니라 상태 주입으로 한정했다.
  - **완료 판정 오라클은 스펙**: "완료 기준" 절 없는 스펙으로는 기동을 거부한다(R9) — 모델 자가평가가 결승선이 되는 것을 차단.
  - **무의존**: Python 3 stdlib만 사용(§16 사다리 5단). Claude Agent SDK의 permission callback 대신 CLI allow/disallow 목록으로 동등 경계를 긋는다 — 이 규모에서 새 의존성보다 낫다.
  - **기존 자산과의 경계**: `/loop`(내장, 세션 안 반복)·carryover(수동 이월)·work-tracker(크로스 세션 정식 추적)를 대체하지 않는다 — autoloop은 "세션 교체가 필요한 무인 반복"만 담당하고, 노트 스키마는 carryover 템플릿을 차용한다.
  - **멀티 엔진(2026-07-19 확장)**: 드라이버는 헤드리스 세션을 `claude -p` 또는 `codex exec`로 돌리며, 역할별 엔진을 지원한다(`--engine`·`--implement-engine`·`--verify-engine`) — "구현은 Claude, 검증은 Codex" 같은 교차 엔진 요구를 충족한다. **Codex 안전 게이트는 sandbox 레벨**(구현=workspace-write·검증=read-only)이라 Claude의 fine-grained allow/deny보다 coarse하다: 네트워크 기본 차단으로 원격 파괴 작업(kubectl·aws·push)은 봉쇄되나 워크스페이스 내 로컬 파괴 명령은 정책 밖이라, 어느 엔진이든 인프라·배포 스펙 금지·blocked 이월이 방어선이다. **bypass 계열은 두 엔진 모두 절대 금지**(§3 완화 불가 — Claude `--dangerously-skip-permissions`, Codex `--dangerously-bypass-approvals-and-sandbox`). 티어→모델 해석은 엔진과 직교로 유지(§9 탈모델명). 스펙 R13~R15, 완료 기준 C16·C17.
    - *(2026-07-26 정정)* 위 "네트워크 기본 차단" 서술은 **조건부다** — 그 값은 설치처 `~/.codex/config.toml`의 `[sandbox_workspace_write] network_access`가 덮을 수 있고 드라이버는 고정하지 않는다(`--sandbox`는 `sandbox_mode`만 덮는다). 따라서 원격 파괴 봉쇄는 이 도구의 보장이 아니라 설치처 설정에 달린 성질이다. 상세·가드레일은 스펙 R3-2.
  - **재기동은 예외가 아니라 상시 경로다(2026-07-30 추가 — 스펙 R16)**: 무인 루프는 세션 한도·프로세스 강제 종료로 **사용자에게 묻지도 못하고 조용히 죽는 것이 정상 동작**이다. 그런데 최초 설계의 재개(R10)는 carryover 노트만 물려받아, 재기동마다 정체 카운터·`seen_valid`·누적 비용·미소진 reviewer 피드백이 0으로 돌아갔다 — 위 게이트 ③이 재기동으로 우회 가능했고, 비용 상한은 작업 예산이 아니라 런당 예산이었다. `state.json` 원자적 체크포인트로 실행 위치를 잇고, **비용 상한은 작업 누적·반복 상한은 런당**으로 갈랐다(전자는 사용자 돈, 후자는 폭주 프로세스 백스톱이라 역할이 다르다). 부수 효과로 `blocked` 정지가 답변 후 재기동으로 이어지는 **인터럽트**가 됐다. 정지 사유는 7종을 그대로 유지했다 — 세부는 로그가 나른다.
  - **게이트 ②의 두 구멍을 같은 변경에서 막았다(2026-07-30 추가 — 스펙 R5-1·R17)**: ⓐ 테스트 결과를 green/red/**error**로 갈랐다. `error`(러너를 실행조차 못 함)를 `red`로 뭉개면 오타 난 `--test-cmd` 하나로 세션이 멀쩡한 제품 코드를 고치며 반복 예산을 태운다 — 원인이 여러 개인데 갈래를 하나로 둔 루프의 전형적 실패다. ⓑ **테스트 래칫**: 세션에 `Edit`·`Write`가 `acceptEdits`로 열려 있으므로 실패하는 단정을 지우면 드라이버가 스스로 green을 보고했다. 지시문 금지 + 검증 세션 BLOCK 조건(완료 기준별 살아 있는 단정)으로 막되, **기계적 diff가 아니라 리뷰어 판정에 의존한다는 잔여 갭**을 스펙에 명시했다(R3-2와 같은 등급).
  - **작업 위치도 게이트다(2026-07-30 추가 — 스펙 R18)**: `--project`가 연결된 worktree 가 아닌 git 저장소면 기동을 거부한다. 무인 세션은 `git add`·`git commit`·`git checkout -b`를 쥔 채 몇 시간을 도는데, 그 대상이 `project/<이름>/`이면 사용자가 쓰던 체크아웃의 브랜치가 밤새 움직인다 — ADR 035가 “절차를 구조로” 바꿔 없앤 실패를 아무도 안 보는 동안 재현하는 형태다. worktree **생성**은 기동 세션(SKILL.md 사전 검사)의 몫이고 드라이버는 만들어졌는지만 판정한다 — 무인 게이트를 넓히지 않으려고 Claude 엔진에 `git worktree` 그랜트를 주지 않았다(Codex 엔진은 도구 목록이 없어 이 부분이 성립하지 않는다 — R3-2와 같은 등급의 갭). 면제 기준점은 `os.getcwd()`가 아니라 **드라이버 파일의 위치**다 — 기동 위치로 잡으면 하위 프로젝트 안에서 기동하는 것만으로 면제가 자기 자신에게 발동한다(독립 검증 실측).
- **스펙**: docs/specs/2026-07-19-autoloop-driver.md (드라이버 완료 기준 C1~C32와 대시보드 관측·자동 기동 계약, 회귀 테스트는 이 변경의 최종 실측값을 `docs/harness-changelog.md`에 기록한다. **이 앞부분은 스냅샷이 아니라 유지되는 포인터다** — autoloop 변경마다 갱신되며(`441e8dc`→`29a20c0`→`6fccf7d`→`9ada413`→2026-08-02→2026-08-19), 그럼에도 `9ada413` 이 기준 수만 C26→C27·55→65 로 올리고 인용한 `Ran 55` 를 남겨 **한 문장이 자기와 어긋난 상태**였다. 뒤따르는 라운드 서술은 그와 달리 그날의 판정 기록이므로 날짜를 박아 그대로 둔다. reviewer 독립 검증: 초기 BLOCK→재작업→PASS, 멀티엔진 PASS. **2026-07-30 체크포인트·분류·래칫 변경은 2라운드 모두 BLOCK으로 끝났고 PASS 판정은 받지 않았다** — 1R must-fix 3건(전부 변경 기록·문구, 드라이버 로직은 통과)과 2R 신규 지적 2건·누락 항목 6건을 반영한 뒤, 잔여가 기계적이라는 리뷰어 판정과 metaskill 「동일 세션 BLOCK 2회+ → 라운드별 fix 중단」 조항에 따라 3라운드를 열지 않았다. 두 라운드의 지적이 같은 계열(변경 기록의 미재현 주장)이었다는 사실도 그 판단의 근거다)
