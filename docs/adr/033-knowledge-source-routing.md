# ADR 033 — 지식 소스를 설계 단계 라우팅에 편입

- **날짜**: 2026-07-26
- **상태**: 활성
- **관련**: ADR 004·005(REGISTRY 분리), ADR 016·030(언어 정책), ADR 032(상시 노출 예산), AGENTS.md §3·§7·§13

## 변경 내용

1. AGENTS.md §7에 8항(지식 소스)을 신설한다. **REGISTRY.md 지식 소스 절에 기록된 경우에만** 발동하며, 신규 프로젝트 생성·기능 스펙 작성·`tool-eval`·**의무·임계·면제·범위·발동 조건을 바꾸는** `metaskill` 변경의 착수 전에 그 절을 읽고 기록된 진입점을 조회한다. "규범적"을 자칭 판단에 맡기지 않기 위해 metaskill 공통 규칙 8이 이미 쓰는 경계를 그대로 인용한다.
2. REGISTRY.md에 지식 소스 절을 신설한다. 상태는 **연결됨 / 없음(확인함) / 미확인** 셋 중 하나이며, 연결됨일 때 진입점과 사용 계약을 함께 기록한다.
3. `harness-install`이 4단계에서 지식 소스를 3계단으로 감지하고, 5단계에서 연결 의사만 질의하며, 6단계 REGISTRY 생성과 7단계 완료 기준에 이를 반영한다.
4. 실제 발동 지점에 절차적 연결을 둔다 — `tool-eval` 1단계(후보군 확정 전)와 `metaskill` 개선 모드. 상시 파일을 키우지 않으면서 선언만 있고 실행 경로가 없는 규칙이 되는 것을 막는다(§8 무결성).
5. 큐레이션 노트(요약 포함)는 **증거가 아니다**. 판단에 반영하기 전 항목의 원문 URL 또는 1차 출처를 확인하며, 출처가 없는 노트는 설계 참고까지만 쓰고 인용하지 않는다.
6. **바깥 방향으로 지식 루트는 기본 `<private>`이다(§3).** 세션 안 판단에는 쓰되, 저장소 밖으로 나가는 산출물(스펙·PR·이슈·커밋)에 인용할 수 있는 것은 따라간 1차 출처뿐이다. 발췌를 프롬프트·리포트로 옮길 때는 §3 untrusted 표시를 단다.
7. 미기록·미확인·확인된 부재는 **발동하지 않으며 고지도 없다**. 기록됐는데 읽기가 실패한 경우에만 경로와 실패한 읽기를 한 줄로 밝히고 진행한다.

## 대상

`AGENTS.md`(§7), `AGENTS.ko.md`, `REGISTRY.md`, `.agents/skills/harness-install/SKILL.md`, `.agents/skills/tool-eval/SKILL.md`, `.agents/skills/metaskill/SKILL.md`, `docs/harness-changelog.md`, `docs/README.md`

## 사유

### 두 종류의 값이 있고, 둘 다 모델이 자력으로 얻지 못한다

검토 대상이었던 `nohdol-study`의 vault는 큐레이션 노트 28건(229KB)과 일자별 기술 큐레이션 170건(월 인덱스 6건·주제 문서 7건 별도, GeekNews 전체 183건)으로 이루어져 있다. 실측 결과 값의 성격이 둘로 갈렸다.

- **설계 입력** — 개념 노트는 사용자가 이미 정리해 둔 설계 축과 후보군을 담는다. 예컨대 에이전트 평가 노트는 궤적·E2E·안전성 3축과 프레임워크 4종 비교를 담고 있고, frontmatter의 `aliases`에 "에이전트 평가 툴"이 들어 있어 사용자 발화 그대로 검색에 걸린다. 이는 모델의 학습 데이터에 없는 **이 사용자의 관점**이며, §13-0 인터뷰와 §13-1 스펙 초안의 입력을 절반쯤 채운다.
- **학습 시점 이후 보완** — 일자별 큐레이션에는 모델의 knowledge cutoff 이후 항목이 쌓인다. 실측 시점(2026-07-26) 기준 cutoff 이후분만 55개 파일 340KB였고(`find -L wiki/GeekNews/2026.6 wiki/GeekNews/2026.7 -name '*.md' | wc -l` = 55), 같은 날 `rg -i "eval|평가|벤치마크"`를 두 디렉터리에 돌리자 모델이 알 수 없는 벤치마크·검증 도구 3건(Senior SWE-Bench 07-03, rubric evaluator 06-11, Semgrep IDOR 06-29)이 즉시 나왔다. 이 축이 없으면 도구 채택 검토에서 **낡은 후보군을 최신인 양 제시하는 실패**가 구조적으로 반복된다.

두 번째 축은 이 하네스 자신에게도 해당한다. 규칙 적용 직전 `rg -N "컨텍스트 엔지니어링|CLAUDE\.md|하네스|스킬 설계|progressive disclosure|시스템 프롬프트"`를 주제 문서 3종(AI와 LLM 에이전트·엔지니어링 철학과 커리어·개발 도구와 셀프호스팅)에 돌린 결과, 하네스 엔지니어링 관련 고득점 항목 6건(75P 04-08, 60P 04-28, 50P 07-04, 43P 06-01 등)과 이 하네스의 멀티 CLI 호환(§11)과 같은 문제를 푸는 외부 도구 1건(VHK, 9P 07-03)이 나왔다(2026-07-26). 트리거 범위에 `metaskill`을 포함한 근거가 이것이다.

### 검색 비용이 낮아 별도 인덱스가 필요 없다

큐레이션 계층 전체(`wiki/`, md 211건 20MB)를 대상으로 한 `rg -l` 검색이 0.04초 내에 끝난다(2026-07-26 `time` 실측, Google Drive 경로 그대로). 임베딩 인덱스가 해결할 병목이 없고, 반대로 인덱싱은 vault 전문을 외부 임베딩 API로 보내므로 §3와 study 하네스의 데이터 정책에 정면으로 걸린다. 지식 루트에 `.env`가 있는 실사례도 확인됐다 — 전량 인덱싱은 시크릿 유출 경로다. **읽을 때만 읽는 방식이 더 싸고 더 안전하다.**

### 요약을 증거로 쓰면 순환 참조가 된다

개념 노트의 절반은 `sources`가 비어 있고, 일자별 큐레이션의 요약은 자동 생성물이다. 이를 근거로 삼으면 모델 생성물을 모델이 자기 근거로 되먹이는 구조가 된다. 다만 일자별 항목은 **원문 URL을 항목마다 보유**하므로 1차 출처로 즉시 내려갈 수 있다 — 발견 신호로서의 값과 증거로서의 무효를 분리할 수 있다는 뜻이고, 사용 계약이 정확히 이 분리를 강제한다. 대상 vault의 주제 문서가 같은 취지의 경고를 이미 본문에 담고 있어, 계약은 새로 만든 것이 아니라 하네스 쪽에 명문화한 것이다.

### 기록된 경우에만 발동해야 하는 이유

지식 루트의 존재 여부는 설치처마다 다르다. 경로를 추적 파일에 넣으면 ADR 005가 REGISTRY.md를 분리한 이유를 그대로 되밟게 되고, 규칙을 무조건 발동시키면 지식 루트가 없는 설치처에서 매번 실패한다. 그래서 조건을 **REGISTRY.md 기록 여부**에 걸었다 — 기록이 없으면 규칙이 실패하는 것이 아니라 존재하지 않는다.

또한 클라우드 동기화 루트는 가용성이 보장되지 않는다. macOS Google Drive는 FileProvider 방식이라 `mount` 목록에 나타나지 않으므로, 링크와 디렉터리가 멀쩡해도 파일이 안 읽힐 수 있다. 감지를 3계단(링크 → 해석 → 실제 바이트)으로 나눈 것은 이 때문이다. `test -r`은 `access()` 권한 검사라 나중에 읽기가 실패하는 플레이스홀더에서도 통과하므로, 실제 바이트만이 판정 근거가 된다. 다만 이 탐침은 `index.md` 한 파일만 보고 클라우드 루트는 선택적으로 실체화되므로, **명백히 깨진 경우를 걸러낼 뿐 모든 진입점의 가독을 보장하지는 않는다** — 잔여 위험은 읽기 실패 시 고지 후 진행이 받는다.

## 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 발동 조건 | REGISTRY.md 기록 시에만 | 설치처별 차이를 규칙이 아니라 데이터로 흡수 (ADR 005와 동일 원리) |
| 트리거 범위 | 신규 프로젝트·스펙·`tool-eval`·**의무·임계·면제·범위·발동 조건을 바꾸는** `metaskill` 변경 | 도구/기술 선택이 결과를 좌우하는 지점에 한정. 구현·리뷰·배포는 제외 |
| 일반화 수준 | 임의 경로 수용 | 큐레이션 인덱스 파일 하나만 요구. 특정 노트 앱이나 특정 하네스에 묶으면 다른 설치처가 배제된다 |
| 경로 기록 | 안정적 심볼릭 링크 우선 | 실제 위치의 정본은 소유 하네스에 남겨 이중 기록과 드리프트를 피한다 |
| 증거 등급 | 큐레이션 노트(요약 포함)는 증거 아님, 원문 URL 확인 필수, 출처 없는 노트는 인용 불가 | §13-2 증거 규칙과 §3 외부 텍스트 취급의 침식 방지 |
| 실패 처리 | 미기록·확인된 부재는 미발동·무고지, **기록됐는데 읽기 실패한 경우에만** 경로와 실패한 읽기를 한 줄로 밝히고 진행 | 클라우드 가용성은 보장 불가. 두 경우를 합치면 지식 루트가 없는 모든 설치처가 트리거마다 영구히 고지를 내야 해서 "발동하지 않는다"는 설계가 무너진다. 고지에 경로·실패를 요구해야 생략과 실패가 기록상 구분된다 |
| 바깥 방향 | 지식 루트는 기본 `<private>`, 인용 가능한 것은 따라간 1차 출처뿐 | 트리거가 전부 **문서 생성** 작업이고 그 산출물은 PR로 나간다. §3의 `<private>`은 태그된 것만 보호하는데 노트에는 태그가 없고, 개인 지식 루트에는 업무 맥락 자료가 섞이기 쉽다 |
| 도달 경로 | `tool-eval`·`metaskill`에 한 줄 포인터 | 다른 §7 조항도 실제 발동 스킬에 절차적 echo를 둔다. 특히 루트 전용 `metaskill` 변경은 라우팅할 프로젝트가 없어 REGISTRY.md를 아예 안 열 수 있다 |
| 검색 방식 | `rg` 온디맨드 | 규모가 인덱스를 요구하지 않고, 인덱싱은 §3 유출 경로를 새로 만든다 |

## 기각한 대안

- **벡터 인덱스 구축(RAG)**: 큐레이션 계층 전체가 0.04초에 검색된다. 얻을 성능이 없는 반면 외부 임베딩 전송이라는 §3 위험과 재인덱싱 유지비가 생긴다.
- **상시 로드**: 지식 루트를 세션 시작에 주입하는 방식. 설계 단계 외에는 쓰이지 않는데 모든 턴의 입력 비용을 올린다(ADR 032와 충돌).
- **루트 REGISTRY.md에 vault 절대경로 기록**: 소유 하네스의 기록과 이중화되어 드리프트한다. 심볼릭 링크 경유로 대체.
- **`없음`과 `미확인`의 통합**: 확인한 부재와 미확인 상태를 합치면 설치 인터뷰가 매 세션 반복된다. 역할 컬럼이 "미확인"을 따로 두는 이유와 같다.
- **부재까지 포함한 일률 고지**: 초안은 미기록·부재·읽기 실패를 한 줄 고지로 묶었다. 독립 검증에서 이것이 "기록 없으면 발동하지 않는다"는 설계 자체와 모순됨이 드러나 분기로 갈랐다(fire-and-fail 회귀).
- **"규범적" 자칭 판단**: 초안은 트리거를 "규범적 metaskill 변경"으로 두었으나, 정의가 없으면 어떤 변경도 다듬기로 자칭해 빠져나갈 수 있다. metaskill 공통 규칙 8의 기존 경계를 인용해 닫았다.
