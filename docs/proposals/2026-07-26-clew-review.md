# Clew(Custos) 검토 — 기각 기록

- 날짜: 2026-07-26 / 상태: **기각** (실측 후 사용자 확정 2026-07-26)
- 대상: https://github.com/JEONSEWON/Clew-by-Custos — PyPI `clew-custos` 0.3.0, MIT, Python ≥3.12
- 관련: ADR 032(토큰 효율형 오케스트레이션), ADR 013(신호 ④ 수축·효율), 루트 AGENTS.md §3·§8, docs/proposals/2026-07-18-graphify-review.md(파일럿 미달 기각 전례)

## 대상 요약

에이전트 트레이스에서 **중복 툴 호출**(`repeat`/`requery`)을 찾아 토큰 낭비를 리포트하는 CLI. LLM 호출이 없는 2단 결정론 캐스케이드다 — ① 구조 게이트: `(노드, 정규화된 입력)`로 묶어 2회 이상이면 후보 ② 동일성 게이트: `sha256(출력A) == sha256(출력B)`여야 확정. 파라미터(`phi=0.514345`, `N=2`, 임베딩 모델)는 git 태그에 동결돼 있고 테스트로 강제된다.

Claude Code 세션 JSONL(`~/.claude/projects/<slug>/<uuid>.jsonl`)을 직접 읽는다. 낭비 1건마다 **증폭 비용**을 산출한다 — 낭비 출력이 이후 모든 턴에 재소비된다고 보고 `낭비 토큰 × 이후 턴 수 × 단가`를 캐시 히트~미스 구간으로 제시한다.

저장소의 자기검증 규율은 수준이 높다: 사전 등록(결과 보기 전 예측 커밋), 동결 파라미터, 공개 철회(작은 표본 결론이 큰 표본에서 무너지면 철회 명시), "구현됨 ≠ 관측됨" 라벨링(`pingpong`은 구현돼 있으나 실측 0건이라 광고하지 않음), 239개 테스트 + CI.

## 실측 (2026-07-26, 격리 venv)

`~/.claude/projects/` 전체 세션에 `clew analyze`를 돌렸다.

| 항목 | 실측값 |
|---|---|
| 분석 세션 | 57개 (1개는 `no timestamps found`로 파싱 실패) |
| 툴 스팬 총계 | 3,759 (측정 시점 기준) |
| 구조 게이트 후보 | 23건 |
| 동일성 게이트 통과 | 2건 |
| **최종 낭비 판정** | **2건 (0.05%)** — 둘 다 `nohdol-study`. **`nohdol-harness` 세션은 0건** |
| 누적 절감 가능액 | **$0.05 ~ $0.50** (57세션 전체 합계, 캐시 히트~미스) |

> 세션 JSONL은 append-only라 스팬 총계는 재측정할 때마다 증가한다(같은 날 재측정에서 3,786 → 3,809). 위 값은 최초 측정 시점의 스냅샷이며, 낭비율은 어느 시점으로 계산해도 0.05%대다. `chain` 루트 스팬(세션당 1개)은 제외한 순수 툴 스팬 수다.

검출 2건의 내용과 판정:

| 세션 | 검출 | 간격 | 도구 자체 단서 | 판정 |
|---|---|---|---|---|
| `dbeebb2a` | `Edit` 중복 (`note-writer/SKILL.md`) | turn 92 → 516 (852턴 중) | "File was modified in between — may be a legitimate re-read" | 위양성 — 424턴 뒤 재편집 |
| `f2f0c4ec` | `Bash` 중복 (`build_graph_test.py` 재실행) | turn 159 → 304 (747턴 중) | "state change uncertain" | 위양성 — 수정 후 재검증 |

`N=2`가 윈도우가 아니라 **발생 횟수 임계값**이라(저장소 `docs/PATTERNS.md` §28), 수백 턴 떨어진 정당한 재검증까지 전부 후보가 된다. 저장소도 이를 recall 상한으로 인정한다.

## 기각 근거

1. **측정 대상 문제가 존재하지 않는다**: 하네스 저장소 세션 낭비 0건. 전체 낭비율 0.05%(2/3,759)이고 그 2건마저 도구 리포트 자체가 정당한 재실행 가능성을 명시한다. 절감 상한 $0.50은 도구 유지 비용을 밑돈다. graphify 기각(파일럿 실측 미달)과 같은 축이다.
2. **`[detect]` 경량 설치가 실제로는 동작하지 않는다**: `__main__.py:144`가 `cr.wasteful`일 때 `embedder.embed()`를 호출해 torch를 요구한다. 즉 **낭비가 검출되는 순간 `ImportError`로 크래시(exit 1)** 하고, 낭비 0인 세션만 정상 리포트된다. README는 "`[detect]`가 검증된 탐지 전부의 출처"라고 하지만 detect-only로는 리포트 생성이 구조적으로 불가능하다. 실질 설치 비용은 **757MB**(torch 2.13 + transformers 5.0).
   - 이 결함은 실측 중 조용한 실패로 나타났다 — 배치 스캔이 "54개 전부 낭비 0"을 냈으나 종료 코드를 따로 잡아 보니 비정상 종료 3건이었다(ImportError 크래시 2건 + `no timestamps found` 파싱 실패 1건). **크래시한 2건이 바로 낭비가 있는 세션**이었다.
3. **판정에 사람 해석 비용이 남는다**: `idempotent` 카테고리는 저장소 자체 집계로 전체의 47%인 회색지대이고, `Bash`·`Edit`는 페이로드 의존이라 `unclassified`로 빠진다. 우리 워크로드는 **툴 스팬의 73.9%가 Bash(42.6%)+Edit(31.3%)** 이라, 검출되더라도 대부분 사람이 다시 판단해야 한다.
4. **성숙도**: star 3의 개인 저장소, 2026-06 생성. 자기검증 규율과 테스트는 훌륭하나 CC JSONL 스키마 변경 시 파손 위험을 감수할 만한 효익이 없다.

## 채택하지 않고 취한 것

**증폭 비용의 계산 구조**만 ADR 032 근거로 반영했다. `낭비 토큰 × 이후 턴 수`라는 형태 — 같은 중복이라도 세션 초반일수록 비싸다는 것 — 이 ADR 032 §2(델타 패킷·재독 금지)를 뒷받침한다. 규칙 변경 없이 사유만 보강했다.

**이 수치를 실측으로 읽으면 안 된다.** 도구가 `dbeebb2a`에 대해 낸 336턴 재소비 / 104,496 증폭 토큰은 ① 낭비 출력이 이후 **모든** 턴에 재소비된다고 가정한 **구조적 상한 추정**이고(도구 리포트 각주가 "estimated saving potential, **not measured**"라고 명시한다), ② 애초에 그 스팬은 위 표에서 **위양성으로 판정한 건**이다. 즉 "실제로 104k 토큰을 낭비했다"가 아니라 "중복이 진짜였다면 이 공식으로 이만큼의 상한이 나온다"가 정확한 독법이다 — 이 문서가 상찬한 "구현됨 ≠ 관측됨" 규율을 이 문서 자신에게 적용한 결과다.

나머지 규율은 **기수렴** 판정:

| Clew 규율 | 판정 | 하네스 대응물 |
|---|---|---|
| 사전 등록(결과 보기 전 기준 고정) | 기수렴 | §13-1·13-3 — 스펙의 완료 기준으로 리뷰 |
| 공개 철회(작은 표본 결론 무너지면 명시) | 기수렴 | §6 ADR 폐기 금지 + 대체 배너 |
| "구현됨 ≠ 관측됨" 라벨링 | 기수렴 | §13-2 증거 4필드 ④ 미검증 범위, §13-5 다크런치 |
| 동결 파라미터 | 해당 없음 | 하네스에 수치 임계값이 없음(있는 것은 R14·R19 바이트 예산이고 이미 테스트로 강제) |

## 재검토 조건

**두 조건이 모두 성립할 때** 재검토한다(둘 중 하나만으로는 부족하다 — 낭비가 없으면 도구가 고쳐져도 쓸 데가 없고, 낭비가 있어도 도구가 크래시하면 쓸 수 없다).

1. **detect-only 크래시가 수정**된다 — `_build_details`가 tool 스팬에서 embedder를 요구하지 않게 되어, torch 없이도 낭비 리포트가 생성된다.
2. **하네스 세션의 낭비율이 유의미해진다** — 구체적으로 harness-review 주간 신호 ④에서 재열람·중복 실행에 기인한 고비용 세션이 2회 이상 관측될 때. 이 판정은 agentsview로 가능하므로 **기각한 도구 없이도 검증된다**. 멀티 에이전트 팀 세션 비중이 늘면 `pingpong` 축(현재 실측 0건, CC 어댑터가 LLM 스팬을 만들지 않아 구조적으로 미발화)이 의미를 가질 수 있다.

재검토 시에도 **채택 형태는 opt-in-per-use 진단 CLI 한정**이다. 상시 훅·자동 라우팅은 이 도구의 판정이 사람 해석을 요구하므로 부적합하다.
