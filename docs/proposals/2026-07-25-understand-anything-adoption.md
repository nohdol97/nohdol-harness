# Understand-Anything 채택 → 철회 (같은 날 재검토)

> **철회 배너(2026-07-25)**: 같은 날 채택 직후 사용자 재검토로 **철회**. 사유: 이 하네스가 같은 세션에 세운 최상위 원칙("사용자 이해는 완료의 요건 — 사용자가 코드를 직접 읽고 이해하며 성장한다")과 **결이 반대**다. Understand-Anything은 코드를 대신 요약·시각화해 그래프·대시보드로 떠먹여, 사용자가 코드를 직접 읽어 이해 근육을 키우는 것을 **우회**시킨다("사람 대면 온보딩" 근거 자체가 "온보딩을 직접 읽기로 시킨다"는 방침과 충돌). 게다가 이미 기각한 graphify와 같은 범주(스테일 그래프)라 캐비어를 잔뜩 달아야 했다. 하네스에서 완전 제거(harness-install 3g·CLAUDE.md 라우팅·explorer/architect 경계·README.ko.md). **도구 자체 금지는 아님** — 개인적으로 쓰고 싶으면 사용자가 직접 설치 가능하나 하네스가 기본 설치·라우팅하지 않는다. **재검토 조건**: 성장 원칙과 양립하는 사용법(예: 그래프를 읽기 보조가 아니라 읽기 유도용으로만)이 구체화되고 사용자가 재요청할 때. claude-video는 코드 이해 우회가 아닌 순수 신규 역량이라 유지(별개 결정).

## 대상 요약

다중 에이전트 파이프라인이 프로젝트를 스캔해 파일·함수·클래스·의존성의 지식 그래프(`.ua/knowledge-graph.json`)를 만들고, 인터랙티브 대시보드(팬·줌·검색·클릭), 가이드 투어(의존성 순 아키텍처 워크스루), 퍼지/시맨틱 검색, diff 임팩트 분석, 온보딩 가이드 생성, 도메인(비즈니스 로직) 뷰를 제공한다. 스킬: `/understand`(초기·증분 분석), `/understand-dashboard`, `/understand-chat`, `/understand-diff`, `/understand-explain`, `/understand-onboard`, `/understand-domain`, `/understand-knowledge`. 증분 재분석(변경 파일만) + `--auto-update` 포스트커밋 훅. 로컬 모델(Ollama) 지원. README 자체 경고: 초기 `/understand`는 대형 프로젝트에서 토큰 소비가 크다.

## 왜 기각(graphify·agentmemory)과 다른가

같은 "코드 지식 그래프" 범주라 기각을 검토했으나, **두 조건으로 리스크 프로파일이 갈라진다**:

1. **직접 호출 전용 → opt-in-per-use**: 자동 트리거를 끄고 사용자의 명시적 `/understand…`에만 돈다. graphify 기각의 핵심(범위 grep 대비 ~17배 토큰이 상시 발생)과 agentmemory 기각의 핵심(세션당 2k 주입+매 호출 훅)이 여기선 성립하지 않는다 — 비용이 사용자가 켤 때만 발생.
2. **사람 대면 강점**: graphify는 모델이 근거로 쓰려다 실패(Dart 줄번호 0%·역추적 빈결과)했는데, 이 도구의 실효 가치는 **사람이 보는 대시보드·온보딩·가이드 투어**다. 그 용도는 줄번호 정확도·역추적에 하네스가 의존하지 않으므로 graphify 실패 모드에 노출되지 않는다.

## 채택 범위 (경계가 곧 안전장치)

- **채택**: 낯설거나 큰 코드베이스에 사람이 처음 진입할 때의 온보딩·내비게이션 보조. 직접 호출(`/understand…`)로만.
- **범위 밖(명시적 금지)**: 하네스 에이전트(explorer·architect)가 `.ua/knowledge-graph.json`을 **진실 소스로 신뢰**하는 것. 코드는 매번 바뀌어 그래프는 스냅샷 시점에 고착되며, 이를 신뢰하면 graphify 실패 모드(스테일 줄번호·어긋난 관계)가 재발한다. 증분 재분석·`--auto-update`가 완화하지만 "증분"은 미변경 파일에 대해 옛 스냅샷을 신뢰하는 구조라 교차 파일 관계가 조용히 드리프트할 수 있다.
- **모델 대면을 굳이 쓴다면**: 라이브 코드로 검증하는 **힌트(후보 파일·관계 리드)로만**, 절대 단독 근거 아님(§13-2 신선한 증거). 이 통합을 실제로 만들려면 별도의 실측 제안이 필요하다(이번 채택 범위 아님).

## 충돌·비용 처리

- **트리거 충돌**: `understand-*` 스킬은 자동 라우팅하지 않는다(직접 호출 전용). 외부 플러그인의 전역 프론트매터는 고치지 않으므로(§11), 강제는 **문서화된 라우팅 정책**(CLAUDE.md 스킬맵 + §7 우선순위 + harness-install 3g)이다 — 기계적 하드 블록이 아닌 모델 준수 규칙임을 정직하게 명시.
- **설치 위치**: 전역(Claude Code 네이티브 플러그인 / 타 CLI는 `~/.understand-anything/repo`) — 추적 저장소를 오염시키지 않는다(§11). Claude Code의 `/plugin` 두 명령은 인터랙티브 슬래시 명령이라 **사용자가 직접 실행**(gh auth login과 동일 패턴).
- **사내 마켓플레이스 차단**: 사내 방화벽·관리형 정책이 `/plugin marketplace`를 흔히 막는다. Claude Code에서 Understand-Anything은 **네이티브 플러그인 전용**(repo의 install.sh는 비-Claude CLI만 지원)이라 마켓플레이스가 막히면 **문서화된 우회 경로가 없어 사유와 함께 스킵**(없어도 무해). 사용자 결정: 강제 유지하되 차단은 자연 스킵으로 처리(개인 프로필 무영향).
- **§3 우려 (프로필로 범위 한정)**: 시맨틱 검색용 **임베딩** 단계가 코드를 프로바이더로 보냄 — 외부 프로바이더면 제3자 유출. **사내 프로필·독점 코드만 로컬 임베딩(`all-MiniLM-L6-v2`, CPU 전용 경량 — 고사양 불필요)을 먼저 켠다. 개인 프로필의 본인·오픈 코드는 불필요**(외부 임베딩 허용 — §3 보호 대상이 아님, 강제는 불필요 마찰). 로컬 *LLM*(Ollama)은 분석 모델 자체로의 전송까지 막는 별개의 무거운 **선택** 태세이지 §3 요건이 아니다(임베딩≠LLM). **이 완화는 proposal뿐 아니라 실행 문서(harness-install 3g)에 실린다** — 런타임 유출은 사용자가 나중에 `/understand`를 돌릴 때 발생하므로, 규칙의 운반체는 설치 시 읽히는 스킬이어야 한다(§12·§3, reviewer F1).
- **경계의 운반체**: "그래프는 진실 소스 아님"은 메인 루프 문서뿐 아니라 실제 수집·설계를 수행하는 `explorer`·`architect` 정의에도 한 줄로 싣는다 — 서브에이전트는 CLAUDE.md/AGENTS.md를 상속하지 않고 자기 정의로 돌기 때문(reviewer F2).

## 실측·재검토

- 3주 실측 게이트는 두지 않음(사용자 결정) — 직접 호출 전용이라 안 쓰면 자연 방치되는 구조라 상시 리스크가 낮다.
- 재검토 트리거: ① 직접 호출 전용 정책이 실제로 안 지켜져 트리거 충돌이 신호 ②로 관찰되면 강제 방식 재설계 ② "그래프를 모델 근거로 쓰고 싶다"는 실사용 수요가 생기면 힌트-검증 통합을 별도 실측 제안으로.
