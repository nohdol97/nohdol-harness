# Test execution evidence — root AGENTS.md §13-2

Long-running commands, including full test suites, redirect stdout/stderr to per-run files under `_workspace/<task>/`; never overwrite earlier logs. Record command, cwd, revision/dirty state, completion status and exit code alongside each log. Read bounded ranges or search the file; display truncation alone never warrants rerunning the command. Missing or incomplete logs remain unverified, not successful. Preserve failure/timeout/cancellation/incomplete status; a log reader's exit code is not the test command's result. Keep root §3's secret and external-output rules.

For the same task, run the full suite at most once after changes and once at final verification, shared across host/workers/reviewers. Hand off consumed slots, command scope, code state and log paths; do not reset the count on fixes, task splitting or delegation. This is a cap, not a quota: do not run unnecessary full suites. Use targeted tests for intermediate repairs, TDD and independent reviewer reruns. Related-test reruns required by reviewer/team-review do not authorize additional full-suite runs. Coordinate ownership before launch so parallel reviewers do not each consume a slot.

If the final suite fails or later edits invalidate its evidence, repair and run targeted tests within scope; report the remaining full-suite validation as unverified. Do not exceed the cap or claim completion using stale evidence. A failed, cancelled or timed-out full-suite attempt consumes its slot. Summary returns contain actual status, relevant results and original evidence paths. Existing safety, SDD/TDD and independent review requirements remain.
