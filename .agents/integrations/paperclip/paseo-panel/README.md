# Paseo Paperclip 패널 0.2

Paseo 사이드바·워크스페이스 패널에서 같은 컴퓨터의 Paperclip 작업을 요청하고 질문에 응답합니다. **화면 조회는 모델을 호출하지 않습니다. 실행 요청·답변·확인·승인·재개·재시도·추가 지시는 에이전트의 모델 호출로 이어질 수 있습니다.** 각 동작을 확인한 뒤 직접 API로 전달합니다.

## 사용 순서

1. 회사를 고르고 프로젝트를 선택합니다. `+ 새 작업`에서 제목과 요구사항을 작성합니다.
2. **초안 등록**은 미배정 backlog로 저장합니다. **작업 실행 요청**은 선택한 담당자를 지정하고 todo로 요청합니다. paused 담당자는 먼저 에이전트 탭에서 명시적으로 재개해야 합니다.
3. **내 응답 필요**에서 질문·확인·승인·차단 항목을 엽니다. 단일·다중 선택, 직접 입력, 필수 조건을 확인하고 답변을 저장합니다.
4. 이슈 상세에서 대기 질문·승인·선행 작업·실패 실행·예약 재시도·일시 정지를 구분해 확인합니다. 선행 작업으로 이동하거나 해당 전용 동작을 사용합니다. 취소된 선행 작업을 완료로 간주하지 않습니다.
5. **추가 지시 보내기**는 단순 메모가 아닙니다. 댓글이 에이전트를 깨울 수 있으며 차단 원인을 자동 해제하지 않습니다.

대기함과 열린 이슈 조건은 앱이 표시되는 동안 30초마다 갱신합니다. 입력 중 내용이 바뀌면 입력을 보존하고 제출을 잠급니다. 다른 곳에서 처리되어 대기 목록에서 사라진 카드도 이전 입력을 확인할 수 있도록 비활성 상태로 남깁니다. 변경 내용을 확인한 뒤 다시 검토하세요. 앱 밖 푸시 알림은 추가하지 않습니다.

**재개**는 선택한 에이전트 전체에 적용되므로 다른 예약·대기 업무도 실행될 수 있습니다. **일시 정지**는 진행 중인 실행도 취소합니다. 여러 역할을 조용히 일괄 재개하지 않습니다. API의 접수·저장 성공은 실제 실행 시작이나 완료를 뜻하지 않습니다.

## 지원 범위

- 조회: 회사·프로젝트·이슈·설명·최근 댓글·에이전트·실행, attention 페이지, 작업 차단 조건.
- 작업: 새 요청, 미배정 초안, 기존 backlog의 담당자 지정 및 실행 요청, 명시적 에이전트 재개·정지.
- 질문: 일반 저장형 및 canonical 질문 세트의 단일·복수 선택·텍스트·사용자 직접 입력. 필수·길이·숫자 범위를 검증합니다.
- 확인: 일반 확인·체크리스트. 대상이 없거나 같은 이슈의 최신 문서인 경우, 또는 명시적으로 해석한 `native_completion_review`를 처리합니다. native 검토 승인은 완료, 거절은 수정 요청으로 전환될 수 있습니다.
- 회사 승인: 필요한 내용이 모두 담긴 알려진 문자열 필드의 `request_board_approval`만 처리합니다.
- 재시도: 현재 예약 실행의 `retry-now`, 서버가 허용한 정확한 failed/timed_out 실행의 전용 wakeup.

**지원하지 않는 요청은 이유와 함께 읽기 전용입니다.** 외부 tool action, secret proposal, 채용·예산·CEO 전략 승인, 알 수 없는 payload/target, 작업 제안 생성, 개별 verdict, 실행 정합성 복구·격리 해제·트리 hold 해제는 Paperclip 전용 화면을 이용하세요. 임의 정규식 검증이 필요한 질문, 20개를 넘는 질문 세트, 전체 내용이 표시 한도를 넘는 확인·문서도 제출하지 않습니다. 모든 관리 기능을 대체하지 않습니다.

## 실행 환경과 설치

Paseo `>=0.11.2 <0.12.0`과 같은 컴퓨터의 Paperclip `http://127.0.0.1:3100`, `local_trusted`를 전제로 합니다. 설치된 Paperclip `2026.1012.0` API를 기준으로 확인했습니다. 인증 모드가 바뀌면 우회하지 않고 오류를 표시합니다.

```sh
cd .agents/integrations/paperclip/paseo-panel
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run typecheck
```

실행 패키지는 Paseo 호스트가 제공합니다. `node_modules`는 검증용이며 배포·커밋에 포함하지 않습니다. Paseo CLI의 `plugin install --help`를 확인해 이 디렉터리를 설치합니다. 사이드바 **Paperclip**, 워크스페이스 패널, 명령 메뉴 **Paperclip 패널 열기**에서 접근합니다. 폰에서는 기존 Paseo 연결을 사용하며 컴퓨터의 Paseo와 Paperclip이 켜져 있어야 합니다. 플러그인은 릴레이·VPN·인증·개인정보 설정을 변경하지 않습니다.

## 요청 안전성과 중복 방지

RPC 입력은 동작별 엄격한 스키마이며 회사·이슈·카드·실행·프로젝트·담당자 소속을 확인합니다. 서버는 고정 `127.0.0.1:3100/api`에만 `node:http`로 접근하며 프록시·리디렉션·임의 URL을 사용하지 않습니다. method/path 조합도 허용 목록으로 제한합니다. 요청 제한은 8초, 응답은 2 MiB입니다.

화면에서 검토한 내용 fingerprint를 제출 직전에 다시 비교합니다. 변경이 있으면 자동으로 최신 내용을 승인하지 않습니다. 상위 일부 API에는 CAS 조건이 없으므로 **검증과 실제 변경 사이의 다른 클라이언트 변경까지 원자적으로 막지는 못합니다.** Paperclip의 최종 권한·상태·문서 버전 검증도 함께 적용됩니다.

실행 요청·초안은 안정적인 작업 UUID를 실제 create idempotency key로 전달합니다. 새 실행 요청은 `allowDuplicate:true`를 사용하므로 같은 제목의 **별도 작업**을 의도적으로 만들 수 있습니다. 같은 요청 재전송은 키로 중복을 막습니다. 기존 draft API 호출자와의 호환을 위해 초안 operationId는 선택 사항이지만 패널은 항상 전달합니다. 결과의 프로젝트·담당자·상태를 확인하며 생성 후 별도의 wakeup을 추가하지 않습니다. 기존 초안을 시작할 때 실행 정책을 덮어쓰지 않습니다.

새 실행·답변·승인·재개·재시도·추가 지시는 서버에서 대상별로 직렬화합니다. 확정된 결과를 영수증으로 저장하고 같은 operation ID는 재실행하지 않습니다. 정확한 실패 실행 재시도는 원래 run ID에도 기록을 묶어, 새 operation ID로 같은 실패를 다시 깨우지 못하게 합니다. upstream wakeup 자체에 일반적인 중복 억제 기능이 있다고 가정하지 않습니다.

실제 변경을 보내기 전에 해시와 결과 영수증만 `~/.paseo/plugin-state/nohdol-paperclip-panel/`에 저장합니다. 요청 본문·토큰·원시 설정을 기록하지 않습니다. 전송 후 타임아웃·연결 단절·응답 검증 실패가 발생하면 대상 잠금을 남겨 자동 재시도를 막습니다. Paseo 연결 오류도 보수적으로 불명확한 결과로 처리합니다. 이 경우 현재 업무와 로컬 영수증을 운영자가 확인해야 하며, **확인 없이 잠금 파일을 삭제하거나 새 요청으로 우회하지 마세요.** 확정적으로 전송 전 거부된 요청만 `outcome:prewrite_rejected`로 구분해 입력 수정 후 다시 검토할 수 있습니다.

## 정보 범위와 제한

agent config·환경 변수·provider context·인증 정보·원시 실행 로그는 반환하지 않습니다. 화면에 필요한 필드만 선택하고 일부 비밀 패턴을 가립니다. 텍스트 마스킹은 완전한 DLP가 아니며, 사용자가 작성한 제목·설명·댓글은 권한 있는 Paseo 연결로 전달됩니다. HTML·Markdown의 외부 이미지·스크립트를 실행하지 않습니다. 이 플러그인은 통계·오류 보고·외부 폰트·추가 외부 요청을 넣지 않습니다. Paseo 자체 전송 채널과 메타데이터 정책은 바꾸지 않습니다.

외부 객체 자동 감지가 명시적으로 꺼진 경우에만 작업·초안·추가 지시 내용을 등록합니다. 설정 확인과 생성 사이의 외부 변경까지 차단하는 전역 네트워크 방화벽은 아닙니다. 로컬 프로세스를 신뢰하는 단일 사용자 환경을 전제로 합니다.

회사·프로젝트·에이전트·이슈 각 최대 100개, 실행 30개, 댓글 50개입니다. 대기함은 페이지당 50개/최대 10페이지, 열린 이슈의 질문·확인·승인 각 30개이며 잘림을 표시합니다. 사라진 편집 카드는 종류별 최대 30개까지 추가 보존합니다. 전체 이슈 집계나 자동 워크스페이스 매핑은 제공하지 않습니다. 확인 문서는 최대 100,000자이며 큰 문서는 읽기 전용입니다.

검증은 모의 HTTP와 실제 조회·화면으로 나눕니다. 테스트를 위해 실제 업무를 생성하거나 에이전트 모델을 실행하지 않습니다. 실물 폰과 실제 실행·답변·승인 결과는 별도 확인 대상입니다.
