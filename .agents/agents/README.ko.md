# 에이전트 카탈로그 (한국어 열람 뷰)

> 생성된 요약이다. 세부 권한과 절차는 `.agents/agents/<이름>.md`의 영어 원본을 따른다. 마지막 재생성: 2026-08-14.

에이전트는 작업을 나눠 맡는 역할이다.

- **수집**: 사실을 모으는 일
- **검증**: 기준에 맞는지 판정하는 일
- **통합**: 여러 결과를 하나로 합치는 일

`사내` 설치처에서는 비용 정책 때문에 서브에이전트를 실행하지 않는다. 유일한 예외는 k8s·IaC를 작성하는 `infra-specialist`다.
이 경우에도 리뷰 역할로는 실행하지 않는다.

## architect

한국어 역할명: 설계 담당.

- **하는 일**: 요구사항과 완료 기준을 스펙 초안으로 정리한다. 완료 기준마다 실행 작업, 선행 작업, 담당 방식, 기대 검증 증거를 연결한 임시 작업 지도를 만들고, 스펙 확정 뒤 오케스트레이터가 이를 확정하도록 넘긴다. 모듈 경계도 설계한다.
- **하지 않는 일**: 제품 코드를 고치지 않는다. 스펙을 확정하지 않는다. 최종 통과 여부를 판정하지 않는다.
- **투입 시점**: 여러 작업의 순서나 인터페이스를 구현 전에 정해야 할 때 사용한다.
- **모델 등급**: design. 설계 오류가 뒤 단계 전체에 퍼질 수 있어 가장 높은 성능을 사용한다.

## explorer

한국어 역할명: 자료 수집 담당.

- **하는 일**: 코드, 문서, 설정, git 이력, 인프라 상태를 읽고 근거가 있는 보고서를 `_workspace/`에 저장한다.
- **하지 않는 일**: 소스와 설정을 수정하지 않는다. 원인을 확정하거나 통과 여부를 판정하지 않는다.
- **투입 시점**: 프로젝트 현황 조사, 파일 탐색, 병렬 자료 수집처럼 읽기만 필요한 작업에 사용한다.
- **모델 등급**: explore. 보통 표준 모델과 낮춘 추론 강도를 사용한다.

## implementer

한국어 역할명: 구현 담당.

- **하는 일**: 배정된 범위의 코드·문서·설정을 수정하고, 실패 테스트부터 작성해 동작을 확인한다.
- **하지 않는 일**: k8s·IaC를 수정하지 않는다. 범위 밖 문제를 함께 고치지 않는다. 자기 결과의 최종 판정을 맡지 않는다.
- **투입 시점**: 제품 코드 구현의 기본 담당이다. 작업 뒤에는 별도 `reviewer`가 검증한다.
- **모델 등급**: implement. 균형형 표준 모델을 사용한다.

## infra-specialist

한국어 역할명: 인프라 담당.

- **하는 일**: k8s, AWS, Helm, kustomize, IaC를 작성하거나 진단한다. 리소스를 만들기 전에 클러스터가 허용하는 CPU·메모리·저장공간 한도를 확인한다.
- **안전 경계**: apply, delete, scale, terraform apply처럼 실행 중인 시스템을 바꾸는 명령은 환경과 관계없이 사용자 확인을 먼저 받는다.
- **하지 않는 일**: 앱 코드를 구현하지 않는다. 리뷰 모드에서는 파일을 수정하지 않는다.
- **투입 시점**: 인프라 파일 변경과 배포 계획에 반드시 사용한다. 작성 시 implement 등급, 리뷰 시 design 등급을 사용한다.

## integrator

한국어 역할명: 결과 통합 담당.

- **하는 일**: 여러 검토 보고서의 중복을 합치고, 근거 없는 항목을 제외한 뒤 필수 수정·권장 수정·관찰 항목으로 정리한다.
- **하지 않는 일**: 새 결함을 찾지 않는다. 코드나 보고 대상 파일을 고치지 않는다. 팀원의 근거를 대신 재현하지 않는다.
- **투입 시점**: 여러 에이전트가 만든 결과를 사용자용 최종 판정으로 합칠 때 사용한다.
- **모델 등급**: design. 최종 심각도와 판정을 결정하므로 가장 높은 성능을 사용한다.

## reviewer

한국어 역할명: 검증 담당.

- **하는 일**: diff와 산출물을 스펙 완료 기준에 맞춰 확인한다. 관련 테스트를 직접 다시 실행하고 PASS 또는 BLOCK을 판정한다.
- **하지 않는 일**: 검토 대상 파일을 수정하지 않는다. 구현자의 완료 보고를 증거 없이 믿지 않는다. 비교를 위해 git 상태를 바꾸지 않는다.
- **투입 시점**: 코드 리뷰, 하네스 변경 검증, 구현-검증 쌍의 마지막 단계에 사용한다.
- **모델 등급**: design. 잘못된 통과 판정을 막기 위해 가장 높은 성능을 사용한다.

## troubleshooter

한국어 역할명: 원인 조사 담당.

- **하는 일**: 실패를 재현하고, 가능한 원인을 세운 뒤 로그·이력·최소 재현으로 하나씩 확인한다. 확정 원인과 수정 방향을 구현 담당에게 넘긴다.
- **하지 않는 일**: 원인이 확인되기 전에 수정하지 않는다. 증거 없는 추측을 원인처럼 보고하지 않는다. 진단을 위해 서비스나 데이터를 파괴적으로 바꾸지 않는다.
- **투입 시점**: 버그, 장애, 회귀, 간헐적 테스트처럼 “왜 실패했는가”를 밝혀야 할 때 사용한다.
- **모델 등급**: design. 원인 오판이 잘못된 수정으로 이어지므로 가장 높은 성능을 사용한다.
